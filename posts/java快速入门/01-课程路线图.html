01-课程路线图 ​

你最终要做出一个可运行的小型 Java 后端项目：一个任务管理 API。它包含任务创建、查询、状态更新、数据库持久化、参数校验、统一错误返回、单元测试和基础日志。

这个项目不大，但它覆盖企业后端最常见的工作动作：读项目结构、改接口、查数据库、处理异常、写测试、解释分层边界。

你要拿到的能力证据 ​

能力你要交付的证据
Java 基础能跑通HelloJava.java、数组和集合练习、命令行输出截图或日志
面向对象能解释Task、TaskService、TaskRepository 的职责说明
API 能用对List、Map、String、LocalDateTime、文件读写练习
Maven 能管理项目pom.xml、mvn test 输出、依赖用途说明
Spring Boot 能开发接口TaskController、TaskService、TaskMapper 或 Repository
数据库能落地建表 SQL、CRUD 示例、分页或条件查询记录
错误能复盘异常堆栈、定位过程、最终修复方案
质量能自证测试用例、验收清单、学习日志

阶段 0：配好能跑的 Java 环境 ​

目标：在固定练习目录里运行第一个 Java 程序，确认 JDK、终端、IDE 和文件路径都可控。

阅读：

  • Jdk、jre和jvm
  • java有哪些版本
  • Java语言开发环境搭建

动作：

bash
cd ~/java-quickstart-course/playground
mkdir -p hello-java
cd hello-java
java -version
javac -version

验收：

  • 你能说清楚 JDK、JRE、JVM 的区别。
  • 你知道当前终端使用的是哪个 Java 版本。
  • 你能解释为什么项目要固定工作目录。

阶段 1：写出最小可用程序 ​

目标：用变量、条件、循环、方法和数组写一个成绩统计命令行程序。

阅读：

  • Java概述
  • 一、变量和数据类型
  • 六、流程控制语句
  • 三、方法入门
  • 1.数组

练习：

  • 输入一组分数。
  • 输出最高分、最低分、平均分和不及格人数。
  • 把计算逻辑拆成方法。

验收：

  • 你能用自己的话说明变量、表达式、语句、方法和数组的关系。
  • 你能改动输入数据并预测输出。
  • 你能指出数组越界、整数除法和空输入会怎样出错。

阶段 2：把过程代码改成对象协作 ​

目标：把成绩统计程序改造成 Student、ScoreRecord、ScoreService 这样的对象协作。

阅读：

  • 面向对象思想概述
  • 类和对象
  • 4.构造函数
  • 封装
  • 接口

练习：

  • Student 只保存学生信息。
  • ScoreRecord 保存学生和分数。
  • ScoreService 负责统计，不直接打印。
  • Main 负责组装数据并输出。

验收：

  • 你能说清楚一个类负责什么、不负责什么。
  • 你能解释为什么服务类不应该直接依赖控制台输入。
  • 你能把“新增等级统计”加进去，而不把所有代码塞回 main。

阶段 3：用核心 API 处理真实数据 ​

目标：用集合、字符串、时间、异常和文件读写处理一份任务数据。

阅读：

  • [String类](./第三部分：核心 API/01-常用 API/String类.md)
  • [ArrayList类](./第三部分：核心 API/01-常用 API/ArrayList类.md)
  • [Map集合](./第三部分：核心 API/02-数据结构/Map集合.md)
  • [日期时间类](./第三部分：核心 API/01-常用 API/日期时间类.md)
  • [异常](./第三部分：核心 API/07-异常与线程/异常.md)
  • [文件和路径](./第三部分：核心 API/06-输入和输出/文件和路径.md)

练习：

  • 从文本文件读取任务列表。
  • 按状态分组统计任务数量。
  • 遇到非法行时记录错误，不让整个程序直接崩溃。

验收：

  • 你能说清楚 List 和 Map 的选择理由。
  • 你能解释 checked exception 和 runtime exception 在练习里的差异。
  • 你能定位输出文件生成在哪里。

阶段 4：把练习项目交给 Maven 管理 ​

目标：用 Maven 管理目录、依赖、测试和打包。

阅读：

  • [Maven 工程的认识](./第七部分：构建与运维/01-Maven/Maven 工程的认识.md)
  • [Maven 常用命令](./第七部分：构建与运维/01-Maven/Maven 常用命令.md)
  • [maven 工程运行调试](./第七部分：构建与运维/01-Maven/maven 工程运行调试.md)
  • 确保所有开发人员maven版本一致

动作：

bash
cd ~/java-quickstart-course/playground
mvn -v

验收：

  • 你能说明 src/main/java、src/test/java、target 分别放什么。
  • 你能用 mvn test 证明代码没有破坏原有行为。
  • 你知道依赖版本应该写在 pom.xml 或统一版本管理里。

阶段 5：做出 Spring Boot 任务 API ​

目标：把命令行任务程序升级成 HTTP API。

阅读：

  • [SpringBoot快速入门](./第六部分：Spring 生态/02-Spring Boot/A-入门/SpringBoot快速入门/SpringBoot快速入门.md)
  • [返回写死数据](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/后端接口开发入门/返回写死数据.md)
  • [请求方式](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/后端接口开发入门/请求方式.md)
  • [接收参数](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/后端接口开发入门/接收参数.md)
  • [返回格式](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/后端接口开发入门/返回格式.md)
  • [全局异常处理](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/全局异常处理.md)

最小接口：

方法路径行为
POST/tasks创建任务
GET/tasks查询任务列表
GET/tasks/{id}查询单个任务
PATCH/tasks/{id}/status修改任务状态

验收：

  • Controller 只处理 HTTP 输入输出。
  • Service 负责业务规则。
  • Repository 或 Mapper 负责数据访问。
  • 异常返回格式统一。

阶段 6：接入数据库并做真实查询 ​

目标：让任务数据持久化，并能做条件查询。

阅读：

  • JDBC基本概念
  • PreparedStatement
  • [MyBatis 框架概述](./第五部分：数据库/02-MyBatis/MyBatis 框架概述.md)
  • [Mapper XML 位置](./第五部分：数据库/02-MyBatis/Mapper XML 位置.md)
  • @Param
  • DO或POJO

验收：

  • 你能解释表、DO、DTO、VO 的差异。
  • 你能指出 SQL 参数从 Controller 到 Mapper 的流动路径。
  • 你能说清楚为什么不能拼接用户输入生成 SQL。

阶段 7：补齐工程质量 ​

目标：把“能跑”升级为“别人敢接手”。

阅读：

  • [Junit单元测试：](./第三部分：核心 API/10-单元测试/Junit单元测试：.md)
  • [参数必填验证](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/请求方式/参数必填验证.md)
  • [优雅地进行参数校验](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/后端快速开发/七、优雅地进行参数校验.md)
  • [创建拦截器来打印请求的信息](./第六部分：Spring 生态/02-Spring Boot/B-接口开发/创建拦截器来打印请求的信息.md)
  • [Spring框架中集成日志打印功能](./第三部分：核心 API/07-异常与线程/Spring框架中集成日志打印功能.md)

验收：

  • 至少 5 个单元测试或接口测试。
  • 至少 3 个失败用例：参数缺失、任务不存在、状态非法。
  • 日志能帮助你定位一次错误请求。
  • 学习日志记录输入、预期、实际、修复和下一步。

阶段 8：把旧实战材料当作升级包 ​

目标：从任务 API 扩展到常见后端需求。

优先升级：

  1. 文件上传：文件上传
  2. 跨域处理：[SpringBoot 项目解决跨域的几种方案](./第十部分：常见需求/SpringBoot 项目解决跨域的几种方案.md)
  3. Maven 多模块：多模块Maven项目
  4. 微服务入口：微服务框架

先不要急着做：

  • 复杂分布式链路。
  • 老项目里的 Hystrix、Swagger2、FastDFS 方案照搬。
  • 没有测试和错误处理的微服务拆分。
