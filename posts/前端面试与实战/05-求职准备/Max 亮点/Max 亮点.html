Max 亮点 ​

本节目标：理解“Max 亮点”的核心思路，并能把它用于实际开发或面试表达。 第1条｜实时行情列表：三层架构技术要点：

  • Quote Worker单例：Worker内维护rowMap排序/价差计算，主线程只收结果
  • 主线程rAF帧聚合：50ms帧节流，同symbol多次报价合并为最后一次diff
  • TanStack Virtual虚拟滚动：自研useStickyOffsets算粘性列偏移，列宽三模式+ResizeObserver自适应
  • provide/inject重构父子状态共享，根除"刷新错位/清空关键词不复原"线上问题

量化： 千级品种 / 20fps平滑刷新 / 主线程零排序计算

第2条｜交易WebSocket全链路技术要点：

  • 基础层：30s心跳 + 指数退避重连（base×2^n，最大30s，20%抖动，最多10次）+ shouldReconnect状态机区分手动/异常关闭
  • 业务层：基于seq的cmd-response RPC（pendingRequests + timeout + reject全部）+ loginInFlight单飞鉴权（强制1.5s最小间隔）
  • 订阅池：Map<moduleKey, Set<symbol>>维护各模块订阅意图，scheduleSync在rAF里合并差异统一下发sub/unsub
  • 帧合流：flushAll一次处理报价diff/订单事件/资金面板三类消息

量化： 弱网自愈亚秒级 / 多面板共享单条ws / 8+模块订阅不冲突

第3条｜万级持仓实时盈亏+账户面板派生技术要点：

  • __profitFactor缓存：首次算factor = PROFIT/(CLOSE_PRICE-OPEN_PRICE)，之后每帧只做factor×(CURRENT_PRICE-OPEN_PRICE)，把币种/合约规模/汇率重算降级为一次乘法；VOLUME变更显式失效
  • 双channel独立批处理：报价进Map覆盖去重，订单事件进数组累积，两个独立500ms useIntervalFn互不阻塞
  • Worker内5份索引：unfoldRows/foldRows/totalStats/categoryStats/statsBySymbol一次循环维护
  • 同品种折叠：Decimal.js加权开仓价+净仓位方向（多/空/对冲识别CMD=6）
  • 分级emit：stats-updated立即推（账户面板秒响应），order-updated走dirty+500ms节流（防列表抖动）
  • shallowRef关键护栏：万行×30字段避免深度Proxy创建
  • 可视行联动订阅池：handleVisibleDataUpdated在rAF内把可视品种推到订阅池，ws推送量收敛到可视区
  • 派生账户面板：Equity=Balance+Credit+Commission+Swaps+FloatingPL，FreeMargin=Equity-UsedMargin，MarginLevel%=(Equity/UsedMargin)×100

量化： 万级订单 / 数十品种 / 高频报价 / 账户3个核心数字亚秒响应

第4条｜K线自定义Datafeed技术要点：

  • 实现完整Datafeed接口：searchSymbols/getHistoryKLineData/subscribe/unsubscribe
  • 实时tick合bar：按周期起点落bar，同bar更新H/L/C，新周期开bar，(ts+bid+ask)三元组去重防volume重复累加
  • 缺口补历史：发现gapBars>1时拉500根历史回填，isFillingGap+gapRetryAfter并发锁防tick风暴重复请求
  • 服务器时区还原：按serverOffsetSeconds把epoch秒还原到UTC，解决GMT+2/GMT+3经纪商K错位
  • 周K对齐：4天偏移对齐周一开盘
  • 18语言热切换：初始化前await syncKlineLocales，与全站i18n联动

量化： 10个周期 / 自研14+画图扩展（斐波那契/ABCD/XABCD/Gann/波浪/箭头等）

第5条｜金融级MFA编排框架技术要点：

  • 注册器模式：5类verifier（email/sms/app/WebAuthn Passkey/主设备验证）注册到registry，按后端返回steps动态加载
  • 循环FSM：while(true){ chooseMethod→doBegin→isPassed?→openStepsDialog→... }，支持switchMethod重试、onRestartFlow切换credential、mfaCleanFn退出时自动清理临时头
  • Policy校验：必选/可选verifier违反时弹RemoteLoginWarningModal终止流程
  • 与HTTP层协同：passageKey注入作用域头，submit时清除

量化： 5类verifier / 出金/改邮箱/远程登录/新设备4种高风险场景 / 新增verifier约1日接入

第6条｜Headless数值输入底座+止盈止损体系两层结构，一条讲：NumericInput（底座）：

  • 四层分层：core纯TS pipeline → composables Vue桥接 → strategy 4种locale → component headless+默认皮肤
  • 三段式pipeline：applyInit/applyInput/applyOperation分相处理，输入中不格式化保护光标
  • 双态展示：聚焦leanTyping（不补尾随零），失焦pretty（按step补零+千分号）
  • 显示层强制trunc截断（禁用四舍五入，防报价被偷涨）
  • 从step反推最小显示位数（解决JS 1.00010被丢成1.0001的坑）
  • 全程Decimal.js+7种舍入模式+IME保护+滚轮throttle 16ms+长按连发+修饰键加速

SLTPField/SLTPManager（业务层）：

  • 4个独立composable：useRange/usePLPreview/useEntryPrice/useBasePrice语义分离
  • direction=tradeDirection×exitType折叠buy/sell×TP/SL四象限，自动推导price/point双轨range
  • 4口径盈亏预览：points/money/percent/sign，全程Decimal.js
  • LazyScope懒实例化：仅有报价且开关开启时创建实例
  • 4个入口共用（市价/限价面板+持仓改单+挂单改单）

第7条｜HTTP中台层技术要点：

  • 解析器链：多个ResponseParser按链路顺序处理，统一抹平后端{code,message,data}协议
  • 作用域临时头/单次临时头：MFA/第三方登录临时注入passageKey/identifierId，命中一次自动清除，useScopedHeaders返回clear()显式控制
  • 全链AbortController取消池：所有未决请求注册到全局池，登出/切账号一键cancelAll
  • useFetch：最后一次请求wins+取消上一请求，防旧响应覆盖
  • 统一401处理：清token→redirectToLogin→useReplace替换栈，UNAUTHENTICATED专门豁免

第8条｜交易订单语义与风控规则技术要点（合并原分散的4条）：

  • Bid/Ask语义：封装持仓/挂单两套报价取值规则（applyQuoteToOrder/calculateOrderCurrentPrice/calculatePendingOrderCurrentPrice），与MT口径对齐
  • 限价单类型推导：基于现价与委托价相对位置自动区分Buy/Sell Limit vs Stop，限价等于现价前置拦截
  • 规格驱动手数：绑定min/max/step_volume，结合账户币种保证金折算计算最大可开手数，Decimal对齐步长
  • 批量平仓：Promise.allSettled+processBatchResults，部分失败逐ticket结构化展示
  • 部分平仓：折叠持仓按子单Math.min拆lots，closingOpenTickets+operationId防重复提交
  • 下单节流：500ms最小间隔+submitting锁，通知用payload.seq做单例替换

第9条｜工程基建：多时区日历Worker+Modal管理器+内容审核编排技术要点：

  • 日历Worker：多品种×多时区sessions_trade+节假日Map+dayjs tz，1s心跳输出isOpen/nextChangeTs/countdown，主线程零计算；交易面板消费isOpen做下单gating
  • Modal管理器：70+弹窗统一注册，modalStore.open('XxxModal', props)返回Promise，全部defineAsyncComponent异步加载，支持跨页跨路由流程恢复
  • 内容审核编排：pass/rate_limited/rewrite_required三分支编排器，用户确认后二次校验，usePersistentCountdown基于sessionStorage跨刷新持久化限流倒计时

第10条｜国际化体系+工程规模技术要点：

  • 18语言（含RTL阿拉伯/波斯，维吾尔/菲律宾/越南/泰/印尼/印地等小语种），29个命名空间分包懒加载
  • 与KLineChartsPro联动：syncKlineLocales初始化前await，避免回退英文
  • 工程规模：32+万行代码/91个业务页面/70+业务弹窗/121个组件子目录/24个API领域/24个Pinia Store/18种语言/5类MFA verifier

三、如何加入简历——具体操作方案先说结论：Boss上的简历不适合放这么多技术细节，Word版简历才是技术负责人岗位的主战场。Boss在线简历（HR看的）工作业绩栏，用我们之前写好的8条三段式即可，不需要再加技术细节。HR看不懂也不需要懂，他的任务是判断"这个人做过金融交易系统"。 唯一要加的一句话，在工作业绩第1条后面追加： 主导构建交易终端完整技术体系，覆盖实时行情（千级品种20fps）、持仓盈亏（万级订单实时计算）、K线图表（10周期+14+自研画图）、MFA安全编排（5类verifier）、18语言国际化等核心模块，工程规模32+万行代码、91个业务页面。 这一句话让HR看到规模感，其他技术细节不要在Boss上展开。

Word简历（技术负责人看的） 这才是放技术细节的地方。在途耀项目下，原来的8条工作业绩之后，新增一块"核心技术亮点"，用以下格式： 【核心技术亮点】 ① 实时行情：自研 Worker+rAF帧聚合+虚拟滚动三层架构， 千级品种20fps平滑渲染，主线程零排序计算 ② 持仓盈亏：__profitFactor因子缓存把币种/合约重算降级为单次乘法， 双channel批处理+Worker分级emit，万级订单亚秒响应， 派生Equity/FreeMargin/MarginLevel%三个账户核心指标 ③ K线Datafeed：自实现历史拉取+tick合bar+缺口补历史+服务器时区还原， 解决"并发tick重入、跨经纪商时差、跨周补K"三类典型疑难 ④ WebSocket全链路：自研带指数退避/心跳/单飞鉴权的WS客户端， seq-RPC+模块订阅池，弱网自愈亚秒级，8+模块共享单条连接 ⑤ MFA编排：注册器+循环FSM串联5类verifier， 与HTTP作用域临时头协同，新增验证方式约1日接入 ⑥ 数值输入底座：四层分层Headless NumericInput（三段式pipeline+ 4种locale策略+7种舍入模式+显示层禁四舍五入）， 作为SLTPField/LimitPriceInput/PriceEditor等4+金融输入入口的统一底座 ⑦ 工程规模：32+万行TS/Vue，91页面，18语言（含RTL）， 5类MFA verifier，14个大业务模块

面试时的口头表达顺序 技术负责人面试时，你的自我介绍可以这样串： "这个项目是面向外汇CFD经纪商的交易终端，我负责Web端80%的核心模块。从用户角度说三个核心场景——看盘、下单、管仓。 看盘这块最核心的是实时行情列表，我们做了Worker+rAF+虚拟滚动三层，千级品种20fps无卡顿。 下单这块最复杂的是止盈止损输入，我把基准价/入场价/范围推导/盈亏预览拆成4个独立composable，加上一个Headless数值输入底座，4个入口共用一套精度无误差的输入框架。 管仓这块核心挑战是万级订单实时盈亏，我做了__profitFactor因子缓存，把每帧重算降级为单次乘法，加Worker+双channel批处理，最终派生出账户净值、可用保证金、保证金率这3个交易员最关心的数字。 底层通信是我自研的WebSocket客户端，带指数退避、单飞鉴权、模块订阅池，多面板共享单条连接，弱网自愈。" 这段话能讲完，技术负责人基本就确认"这个人真做过"了。
