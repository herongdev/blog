# 自动解包

> 本节目标：理解“自动解包”的核心思路，并能把它用于实际开发或面试表达。
在 Vue 的模板里，**只有作为“顶层”绑定的 Ref 会被自动解包**。具体来说：

1. **ref() vs reactive()**
    - const x = ref(1)：x 是一个含有 .value 的对象，Vue 会在模板里把 x 当成原始值 1 来渲染。
    - const state = reactive(\{ foo: ref(1) \})：此时 state.foo 本身是一个 Ref，但它被包在一个 Reactive 对象里。Vue 在模板里读取 state.foo，只认为它是个普通属性，**不会**继续去拿它的 .value。
2. **自动解包规则**
    - **顶层变量**：你在 \<script setup\> 里写了 const count = ref(0)，模板里写 \{\{ count \}\} 或 :value="count"，Vue 会自动渲染成 0。
    - **嵌套属性**：如果你写 :value="state.count"，哪怕 state.count 是个 Ref，也会渲染成 [object Object]，因为 Vue 只做了一层“取属性”，没再去取那一层的 .value。
3. **为什么用 toRefs 解决******当你对 state 做 const \{ formattedValue \} = toRefs(state)，就把 state.formattedValue 这个 Ref **提升**成了一个“顶层变量” formattedValue。模板里 :value="formattedValue"，这次就符合自动解包规则，Vue 会展示 formattedValue.value 的内容，而不是整个 Ref 对象。

**总结**：

- **自动解包只针对顶层响应式引用**，不会递归地把 Reactive 对象里的 Ref 给拆开。
- 如果你想让嵌套在 Reactive 对象里的某个 Ref 在模板中也自动解包，就必须把它“拆”到顶层，最常用的做法就是 toRefs(state)。
