# 实际应用

> 本节目标：理解“实际应用”的核心思路，并能把它用于实际开发或面试表达。
既然 SuperMapLegend 是 SuperMap 的子组件，我们可以使用另一种方法来告知 SuperMap 有 SuperMapLegend 子组件存在。这个方法基于 Vue 3 的生命周期钩子和 setup 方法的上下文。
以下是这种方法的具体步骤：

在 SuperMap 中，提供一个方法供子组件调用来设置 hasLegend。
在 SuperMapLegend 中，在挂载时调用父组件提供的方法。
代码示例如下：
SuperMap.vue:
vue
Copy code
\<script setup\>
import \{ ref \} from 'vue';
const hasLegend = ref(false);
const registerLegend = () =\> \{
hasLegend.value = true;
\}
provide('registerLegend', registerLegend);
\</script\>
\<template\>
\<div\>
\<!-- 地图相关的内容 --\>
\<!-- 如果有图例则显示相关内容 --\>
\<div v-if="hasLegend"\>
Map has a legend!
\</div\>
\<!-- SuperMap 的其他子组件 --\>
\<slot\>\</slot\>
\</div\>
\</template\>
SuperMapLegend.vue:
vue
Copy code
\<script setup\>
import \{ inject, onMounted \} from 'vue';
const registerLegend = inject('registerLegend', null);
onMounted(() =\> \{
if (registerLegend) \{
registerLegend();
\}
\});
\</script\>
\<template\>
\<!-- 图例内容 --\>
\</template\>
这种方法确保了，只有当 SuperMapLegend 是 SuperMap 的子组件并被挂载时，SuperMap 才会知道其存在，并据此更新其状态。

这个方案能确保一个项目中有多个superMap实例时不出问题吗，如果可以的话，算是一种方案，还有别的方案吗
ChatGPT
对于您的问题，前面提供的方案确实可以工作，因为每个 SuperMap 实例都会提供自己的 registerLegend 函数，这意味着每个 SuperMapLegend 只能与其直接的父 SuperMap 实例进行交互，而不会影响到其他的 SuperMap 实例。
不过，你是对的，我们应该考虑更多的解决方案。以下是另一个可能的解决方案，基于Vue 3的 ref 和 provide/inject 机制：
使用ref进行交互
SuperMap 提供一个 ref 供其子组件进行设置。
SuperMapLegend 注入这个 ref，并在它被挂载时修改该 ref 的值。
SuperMap.vue:
vue
Copy code
\<script setup\>
import \{ ref, provide \} from 'vue';
const hasLegend = ref(false);
provide('legendStatus', hasLegend);
\</script\>
\<template\>
\<div\>
\<!-- 如果存在图例则显示相关内容 --\>
\<div v-if="hasLegend.value"\>
Map has a legend!
\</div\>
\<!-- SuperMap 的其他子组件 --\>
\<slot\>\</slot\>
\</div\>
\</template\>
SuperMapLegend.vue:
vue
Copy code
\<script setup\>
import \{ inject, onMounted \} from 'vue';
const legendStatus = inject('legendStatus');
onMounted(() =\> \{
if (legendStatus) \{
legendStatus.value = true;
\}
\});
\</script\>
\<template\>
\<!-- 图例内容 --\>
\</template\>
这种方法的优点是简单且直接：SuperMap 通过 provide 提供了一个 ref，子组件可以修改这个 ref 的值来通知父组件。由于每个 SuperMap 实例都提供了自己的 ref，所以这不会影响到其他的 SuperMap 实例。
不过，两种方案其实都是基于相似的概念，即使用 Vue 3 的 provide/inject 机制来实现父子组件之间的通信。选择哪种方案取决于您的具体需求和对代码简洁性/可读性的偏好。
