# 组合式api

> 本节目标：理解“组合式api”的核心思路，并能把它用于实际开发或面试表达。
背景：
通过封装组件，我们可以将界面中重复的部分连同其功能一起提取为可重用的代码段。仅此一项就可以使我们的应用在可维护性和灵活性方面走得相当远。

然而，我们的经验已经证明，光靠这一点可能并不够，尤其是当你的应用变得非常大的时候——想想几百个组件。处理这样的大型应用时，共享和重用代码变得尤为重要。

作用：

- 将同样的业务逻辑放在一个地方，然后这个业务逻辑返回一个值和一个更新这个值的方法，类似于react的hooks;
- 为了使些返回的值具备响应性，可以使用ref和toRefs来对值进行包装；

为了开始使用组合式 API，我们首先需要一个可以实际使用它的地方。在 Vue 组件中，我们将此位置称为 setup。

要点：

- 执行时机：setup 选项在组件创建之前执行，一旦 props 被解析，就将作为组合式 API 的入口。所以在 setup 中你应该避免使用 this，因为它不会找到组件实例。setup 的调用发生在 data 、computed 或 methods 被解析之前，所以它们无法在 setup 中被获取。
- 返回一组值，这组值可以在data, computed和watch中直接使用；
- 内部可以使用生命周期中的逻辑，即使用on+生命周期函数；
- 内部还可以使用watch和computed;

setup参数：
setup 选项是一个接收 props 和 context 的函数。此外，我们将 setup 返回的所有内容都暴露给组件的其余部分 (计算属性、方法、生命周期钩子等等) 以及组件的模板。

setup中代码逻辑：

- 定义变量
- 定义修改变量的的函数
- 返回变量和函数，以便其他组件选项可以对它们进行访问
- 看是否要定义生命周期钩子；组合式 API 上的生命周期钩子与选项式 API 的名称相同，但前缀为 on：即 mounted 看起来会像 onMounted。
- 看是否要定义watch响应式更改：就像我们在组件中使用 watch 选项并在 user 上设置侦听器一样，我们也可以使用从 Vue 导入的 watch 函数执行相同的操作。它接受 3 个参数：
    - 一个想要侦听的响应式引用或 getter 函数
    - 一个回调
    - 可选的配置选项
- 看是否要添加计算属性：computed 函数传递了第一个参数，它是一个类似 getter 的回调函数，输出的是一个只读的响应式引用。为了访问新创建的计算属性的 value，我们需要像 ref 一样使用 .value。
