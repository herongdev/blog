# 视频选择反馈与平台发布衔接

日期：2026-11-05（Asia/Shanghai）。本轮代码、构建、下述 Edge 验收及后台部署已完成。没有真实平台投稿，也没有切换云存储。

## 用户目标与问题边界

用户报告内容工作区“视频”页点击“选择视频”没有反应，并希望选好视频后进入各平台发布，同时询问 COS、TOS 是否可存储视频。

实际核对得到：

- 原选择按钮同步调用已挂载的文件 input；input 不随页签卸载。不能仅因 `display: none` 就认定它是故障原因，本轮保留原选择器机制。
- 已运行 Microsoft Edge 的现有窗口中新开标签，在 `127.0.0.1:4387` 隔离环境实际点击按钮，可以打开原生文件框。选取约 2 KB 的真实 H.264 MP4 后，上传及视频预览成功。
- 线上只读查看用户的 Codex 图标条目，已有约 4.4 MB 的 MP4 成片且为已选用状态。这能证明条目存在已保存的视频，不能确认它是否来自用户报告的那次点击，也不能排除当时发生的浏览器或网络问题。
- “没有反应”具体指未弹文件框，还是选完后没有上传反馈，尚未得到用户答复；COS/TOS 的期望用途也尚未确认。下面的修复针对已确认的反馈和流程缺口，不将猜测写成选择器故障结论。

## 本次修改

- 选完文件立即显示文件名、0 字节和“准备上传”，覆盖创建上传意图及首个分片完成前的等待；每个文件分别重置进度。
- 传输阶段按已完成分片显示真实字节数；最后分片之后改为“校验并保存中”和不定量进度，不再把传输 100% 表现为文件已经保存。保存阶段禁用暂停，失败仍保留错误与继续上传入口。
- 视频页的“选择账号与发布”直接进入发布中心账号及文案配置，省去先进入内容发布页再点一次的步骤。内容发布页共用同一入口；等待桥接完成并显示准备状态，同步锁防止重复点击。
- App 等待视频桥接请求后再切换发布中心，失败交回内容工作区显示。用户切到其他条目后，旧响应不能将页面导航回原条目的发布配置。进入发布中心不会自动提交作品。
- 成片文件选择及服务端发布桥接统一为 MP4、MOV、M4V、WebM；MKV 不作为成片进入投稿流程，但仍可作为原始录屏保存在制作素材中。服务端仍校验真实媒体内容，文件选择器后缀过滤不能代替校验。

主要实现为 `author/src/ContentWorkspace.tsx`、`author/src/App.tsx`、`author/content-workspace.mjs` 与 `author/workspace-api.mjs`。本轮没有重做页面结构，沿用现有工作区、语义颜色、Radix、Lucide 及既有确认发布流程。

## COS / TOS 的实际能力

两家官方均提供 S3 兼容接入说明，见 [腾讯云 COS 的 S3 兼容说明](https://cloud.tencent.com/document/product/436/50743)和 [火山引擎 TOS 的 AWS S3 SDK 接入说明](https://docs.volcengine.com/docs/torch-object-storage/accessing-tos-using-awss-3-sdk?lang=zh)。项目现有 `workspace-s3.mjs` 可按目标服务的 endpoint、region、bucket 和受限凭据配置私有视频存储；这说明源码有接入路径，不代表本轮已验证真实云账号。

现有链路为：浏览器分片 → 已鉴权的作者服务 → 媒体校验 → 私有对象存储；读取和投稿桥接继续经过服务端。当前仅配置一套 S3 目标，不提供云桶文件浏览器、双云同时保存、浏览器 STS 直传或公开视频 URL。长期凭据只在服务器配置，不下发浏览器。

线上仍使用本机私有存储。本轮未新增 provider 选择界面、未启用 COS/TOS 凭据、未更改桶权限、未迁移既有视频；真实云端上传、读回和平台桥接尚未验收。配置说明仍见 `author/workspace.env.example`。
