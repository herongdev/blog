# 内容工作区、制作素材与发布生命周期设计

日期：2026-11-03（Asia/Shanghai）。状态：现状审计与设计建议，未实施、未部署。本次只读本地代码及既有上线记录，未连接生产服务器或操作云存储、平台账号。设计供现有写作台渐进改造使用，不迁移主站、不引入另一套 CMS。

## 1. 用户与目标

用户是独立制作开发工具教程的作者。日常从本周或其它选题中选一条，写文章、录制和剪辑视频、投放不同渠道；数月后能找到原始工程和素材修改内容。需要少切页面、不重复填标题、不丢稿、不误发布、知道每个平台实际发生了什么。

核心模型：一条内容拥有稳定身份；文章、视频、制作素材和发布记录属于这条内容。排期只决定哪周拍，不决定能否编辑或发布。不在本周的条目也能完成全部操作。内容可先发文章、后补视频，也可只发一种形式。

## 4. 页面与日常操作

保留上下排列的本周/其它，条目尽量一行。标题、简短文章/视频状态、一个当前主操作及更多菜单同排。已拍勾选、拖动边界与撤销规则不变。

示意（只表达结构，不是现有业务状态）：

`拖动 · 标题 · 文章草稿 / 视频未上传 · 写文章 · 已拍 · 更多`

主操作可以随实际情况变为“继续写”“上传视频”“发布”“编辑”；所有操作仍可通过标题进入工作区找到，不强制先写完文章才能上传视频。更多菜单提供文章、视频、制作素材、发布记录、调整排期和归档入口；下架在发布目标内确认，避免一个全局按钮影响所有渠道。

点击任何列表中的同一标题，打开同一个内容工作区，保留返回时的搜索、分页及滚动位置。工作区四个页签：

| 页签 | 常用操作 |
| --- | --- |
| 文章 | 写作、保存/自动保存反馈、预览、工作稿与线上版切换、历史恢复 |
| 视频 | 上传成片、播放、选用版本、横竖版变体、封面、字幕、口播稿/拍摄备注 |
| 制作素材 | 原始录屏、图片、音频、工程文件；批量上传、目录、引用、下载素材包 |
| 发布 | 勾选网站/平台账号、分别预览文案与文件、提交、查看真实状态及历史、更新/下架 |

全局保留排期、内容库、发布任务；账号放发布设置中，通用素材库按需进入。单人创作第一版不增加多人审批、复杂看板、在线剪辑器或大量统计卡片。

## 5. 状态与版本必须分开

| 维度 | 含义与推荐表达 |
| --- | --- |
| 排期 | 本周、其它、历史安排 |
| 拍摄 | 待拍、已拍；已拍不等于剪完或公开 |
| 文章修订 | 草稿、待发布、已发布、有未发布修改 |
| 视频制作 | 未上传、上传/校验中、成片可用；录制原片和发布成片明确分开 |
| 每渠道公开状态 | 未发布、提交中、待核实、审核中、已公开、失败、已下架；仅显示有证据的状态 |

列表显示少量能指导下一步的状态；完整细节进入工作区。汇总只能说“部分已发布”等实际状态，不能将多平台压成一个容易误导的“已发布”。平台返回已受理也不能自动标为已公开。

文章需要 `workingRevision` 和 `publishedRevision`。改稿只更新工作版本。发布本文时固定文章与引用素材的修订，正式站构建来自所有文章的已确认版本集合，只有被选择的文章推进版本。构建失败，原线上版本与记录保持一致；成功激活后再确认新的公开版本。预览与正式使用同一快照，确认后不混入后来编辑。

历史恢复先产生新工作稿，不自动回滚线上。支持自动保存的明确反馈、并发冲突和离页未保存提醒，不能用浏览器本地存储作为唯一副本。

视频上传新版本不替换正在投稿的文件，也不自动更新外部平台。网站文章 URL 保持稳定；视频保留各平台作品 ID、链接、所用版本和核对时间。

## 6. 制作素材包：目标是可继续剪辑

素材包是有版本和清单的资产集合，可按需导出 ZIP，也可原样保留剪辑软件导出的完整工程包。建议包含：

- 原始录屏、拍摄文件，以及用于制作的截图/插图。
- 原始配音、配乐、音效，保留来源与必要授权记录。
- 口播稿、字幕、分镜和纠错说明。
- 封面源文件与输出图；剪辑工程文件。
- 最终成片与渠道变体，并标记本次采用的版本。
- 软件及版本、插件/字体依赖、文件相对目录、文件大小与校验和、缺失依赖说明。

只存工程文件未必能重开：它可能引用作者电脑上的外部文件。先用剪辑软件的收集/归档能力形成可搬走的项目，再上传；不假设某一种剪辑软件必然支持同一种打包格式。软件未知时提供通用文件夹/工程包上传，专用自动收集在实际工具确定后实现。

原始字节不缩放、不重新编码、不覆盖；缩略图、预览转码另作衍生文件。公共片头、Logo、常用音效可作为共享素材被多条内容引用，每次发布固定具体版本，替换公共素材不回写历史作品。

一期可保留不透明工程 ZIP 的原包，但“已上传”不能宣称“可恢复”。支持可读清单、说明和缺失项，后续以实际下载后重开工程验收。若服务端读取或解压包，须限制总大小、文件数和路径，拒绝目录穿越与恶意压缩包。

## 7. 对象存储与资源生命周期

建议沿用当前对象存储供应商，通过独立私有制作素材桶保存原始素材、工程与成片。已有公开文章图片域名继续承载明确发布的衍生图片；私有工程、原片及其文件名清单不可落入该公开前缀。

上传路径：已登录用户申请绑定内容与文件的上传意图 → 获取最小权限临时凭证 → 浏览器分片直传 → 服务端核验真实对象、归属、大小/摘要与必要的媒体解码 → 登记为可用资产。上传成功和素材验证成功分别反馈。续传记录不能泄漏长期密钥或签名 URL；刷新后按浏览器能力恢复，无法重新取得原文件时如实要求重新选择。

官方实现依据：[TOS 浏览器断点续传与临时凭证](https://docs.volcengine.com/docs/torch-object-storage/resumable-upload-browserjs-sdk?lang=zh)、[OSS 浏览器授权方式](https://help.aliyun.com/en/oss/developer-reference/authorize-access-6)。具体 SDK 在实施时按实际供应商接入，不能假设 S3 普通上传接口已经具备完整浏览器续传。

私有预览/下载使用鉴权与短时授权。业务引用资产 ID 和不可变版本，不保存即将过期的签名地址。自站播放不是本期必需：可先保存母版并跳转平台成片；若需要自站播放再评估转码、分发与播放流量。

平台执行器目前需要本地文件，可按任务下载准确版本到有额度的临时缓存。核验摘要后执行；任务仍在读时不删除，完成/恢复确认后按保留策略清理。不把所有云端素材常驻缓存到服务器，也不在打包 ZIP 时占满系统盘。

生命周期约束：

- 正在制作的内容、已发布引用及其源工程不能仅按年龄自动删。
- 未完成分片、失败临时文件可按有界策略回收；孤立文件有宽限期和引用检查。
- 从某条内容移除引用，不等于删除共享文件；归档条目不等于平台下架。
- 原始素材/发布版本默认保留；回收站及保留时长在实施时明确，容量不足先提示影响范围。
- 冷存储仅对确认归档、低频取用的资料启用，展示恢复等待及取回成本；近期可能重剪的工程保留热存储。
- 对象存储不等于备份。备份文章、SQLite 一致快照、素材清单和版本引用，并有独立副本与恢复演练；不继续每天把全部大视频重复打进同机归档。
- 展示总用量、各内容占用、历史版本及临时缓存占用；预算要考虑存储、预览/下载流量、请求、取回与备份。未查询实际账户账单，不给虚假月费。

## 8. 发布、更新与下架的真实边界

一次发布可以选网站及多个平台，但目标分别执行、记录和重试，不能承诺跨外部平台原子成功。某个平台失败保留其它成功结果；结果未知先核对，不自动重复投稿。执行中编辑文章或上传新视频不改变这次任务的固定快照。

| 操作 | 网站 | 外部平台 |
| --- | --- | --- |
| 发布 | 选定版本通过原发布器上线；保留教程可见性/实测门槛 | 复用现有适配器，逐账号取得实证后确认状态 |
| 修改文案 | 另存工作稿，确认后更新线上 | 按已验证平台能力更新；无接口则打开平台管理并记录人工核对 |
| 更换成片 | 可按网站能力指向新版本 | 不保证原作品原地替换；可能需新作品，保留旧新关系 |
| 下架 | 发布排除清单，页面、站内搜索、站点地图/RSS及缓存按策略同步处理 | 确实支持才执行；否则引导平台操作，不能本地改状态就视为已下架 |

[YouTube 官方说明](https://support.google.com/youtube/answer/55770/replace-or-delete-your-video-computer?co=GENIE.Platform%3DDesktop&hl=en-GB)明确新上传视频产生新 URL，不能普遍假设所有平台都支持替换。这个例子只说明能力应逐平台建模，不代表已经接入 YouTube 或其它平台拥有相同限制。

下架、删除、归档分开。下架保留内容与制作源文件；第三方已下载副本和缓存无法承诺立即撤回。自站下架页面与公开文件撤权是两项操作，需依据文件引用与缓存策略处理，不误删别篇仍使用的图。

## 9. 渐进实施与验收

建议继续使用现有 React/Node 写作台、Markdown 与 SQLite，不拆微服务。增加稳定 contentId，兼容现有 slug/URL；增加内容与资产版本/素材包/发布目标关系。Markdown 继续作为文章正文唯一编辑来源，数据库管理关联、修订与发布指针，避免两份正文各自可写。

1. 先贯通一条内容：工作区、文章/视频/发布记录关联、逐篇工作稿与线上版分离。现有排期稳定关联，保持已拍固定顶部。
2. 同一首期交付补齐私有素材：对象存储、分片上传、素材包、原片/成片版本、下载恢复。保留本地存储兼容读取，逐项迁移、校验后才能回收旧文件。
3. 复用发布器完成所选内容与账号的确认发布和真实状态；首期就有平台人工管理入口。自动更新/下架、定时发布、跨平台分析在逐平台能力实测后逐步增加。

关键验收：

- 本周、其它、内容库打开同一内容；移动排期不丢素材、版本与发布记录。
- 文章 A 发布时，不包含文章 B 的未确认修改；预览之后再修改 A 不改变已确认发布快照。
- 发布失败保留原线上版；公开搜索只读已确认且允许公开的数据。
- 原片、工程、草稿和包清单匿名不可读；发布一张图不会连带开放整个包。
- 大文件中断可续传；重复提交不重复入库；错误类型/归属拒绝；错误部分可单独重试。
- 下载一个真实工程包，在临时目录中重开编辑软件核验依赖，原目录不参与寻址；不把“ZIP 下载成功”算恢复成功。
- 共享素材移除引用不误删其它内容；发布快照所引用版本保持可取回。
- 一个平台成功、另一个失败/未知时分别呈现；未知不自动重投；取消任务不标为下架。
- 实际查看桌面/窄屏、明暗主题和键盘操作；与功能测试分别报告。全流程用隔离数据，真实投稿另按本人所选内容操作。

本次交付为上述设计与参考核验，未修改产品代码、生产数据或发布任务；没有将方案标为已实现。
