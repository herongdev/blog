## 用户要求与范围

用户要求实施一版共享目录与拍摄工作区，并按视频对实际工作是否有用重新判断原半年选题；没有足够价值的退出待拍池，即使只剩几条。不再维持每周三条、半年数量或工具品牌均摊。

定位依据是 `docs/dev-guides/source-registry.md`：用 AI 工具开发、维护和交付真实项目的中文开发者。判断对象是工作问题、操作结果与可验证的收益；基础操作也可以有价值，不能仅按是否新颖、是否高级筛选。

整理范围为原导入的 130 条计划/备选和 8 条近期候选。用户后来手动新建的条目、非该批导入的旧稿保持原样。退出待拍池采用可恢复归档，不删除 Markdown、上传素材、文章历史或公开版本。旧研究 JSON 与题卡作为历史来源保留，不冒充用户原始笔记。

## 产品结构与参考

实现前实际查看了 [Todoist 官方分组列表](https://www.todoist.com/help/todoist/features/introduction-to-sections-rOrK0aEn) 与 [Notion 官方侧栏截图](https://www.notion.com/help/navigate-with-the-sidebar)。采用紧凑侧栏与分组列表，保留项目已有配色 token、明暗主题、Radix 与 Lucide。

- 排期和内容库读取同一目录树；目录归属与拍摄次序独立。支持多级、兄弟排序、移入子目录、内容拖入目录，以及菜单/键盘替代操作。
- 本周保留平铺列表；目录筛选只改变候选视图。拖入本周不改变目录，归类不改变拍摄次序。
- 从排期进入“选题与拍摄”，准备目标、提纲、清单和备注独立保存；文章、成片、制作素材及发布仍在同一内容下。
- 历史调研资料只读保留。三个复用原稿的选题也关联完整来源，不以资料覆盖作者当前正文。
- 已归档入口可查看和恢复。恢复只回活动内容库，需手动重新加入排期，不复活旧拍摄任务。
- 目录只由保留题的真实工作用途产生，不提前增加无关分类；旧生成目录只有在来源记录、路径和无占用均核对后才清理，回执保留原结构。

## 数据与部署边界

共享目录及归档生命周期保存在私有 `.library.json`；拍摄准备与来源保存在 `.filming.json`；离线整理回执保存在 `.editorial-curation/`。新私有数据排除于代码包、Git 和 Vite 文件访问，随项目完整备份。

## 回滚边界
