# 抖音登录二维码恢复

日期：2026-11-05（Asia/Shanghai）。本轮已修复执行环境的进程/线程限额，并上线分阶段错误反馈。已通过既有 Microsoft Edge 窗口中的后台实际生成抖音登录二维码；本人未完成扫码，该次操作最终为登录超时，不能称账号已登录或视频已投稿。

## 故障与根因

用户点击抖音扫码登录后，后台在二维码出现前结束，并显示“账号尚未登录或会话已失效，请重新登录”。生产记录中的失败操作均为 `login`，二维码版本为 0；这不能证明用户未扫码或既有会话过期。

在真实服务账号及同等 systemd 约束下，对公开抖音登录组件进行隔离诊断，得到以下对照：

| 条件 | 结果 |
| --- | --- |
| `MemoryMax=2 GiB`、`TasksMax=128` | 约 5.5 秒出现 `Page.goto: Page crashed`，二维码未生成；`pids.events` 的 `max` 为 2，内存 OOM 事件为 0。 |
| 仅将 `TasksMax` 改为 512，其他条件相同 | 约 24.5 秒生成二维码；`pids.events max=0`，无内存 OOM。 |

该对照确认本次浏览器页面崩溃的原因是 cgroup 的进程/线程上限，不是二维码选择器失效或账号会话过期。诊断使用 `max_checks=0`，只获取二维码，不等待本人扫码；因此最终返回 `timeout` 是主动停止验证的预期结果，不能写成扫码超时故障，更不能写成登录成功。

## 修复边界

- 作者服务的 `TasksMax` 从 128 调整为 512，保留 `MemoryMax=2147483648`、原文件系统和安全隔离约束。
- Node 保留执行器的 `logging_in` 阶段，不再把它降为没有具体含义的 `working`。
- 登录结束结果采用受控错误码及固定安全文案，区分登录页不可用、未取得二维码、登录超时、登录未完成及暂时无法检查会话。不将原始异常、stderr、平台 URL、账号文件路径或凭据写入会话记录及 API。
- 登录准备失败使用 `auth_status=unknown`，不冒称账号已经失效；正常检查明确返回 `invalid` 且没有运行错误码时，仍为已完成检查、未登录或已失效。成功和取消语义保留。
- 本轮没有改动 SAU 登录页面选择器或受控补丁，没有自动提交任何作品。
