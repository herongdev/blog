# 抖音二维码同步与重新获取

日期：2026-11-05，Asia/Shanghai。

## 问题与证据

用户反馈新二维码出现后立即扫码仍提示过期，页面显示的截止时间尚未到。本轮不能把这一反馈解释为用户扫码太慢，也不能把二维码可显示当作手机扫码成功。

上一版存在三个已确认的问题：

- SAU 只在出现精确“二维码失效”文字时重新发送图片，没有跟随平台自动换图。
- 每次回调自行标注五分钟有效期，界面却显示十分钟登录任务截止时间；两者都不是抖音承诺的二维码有效期。原执行器实际约两分钟结束等待。
- 重新点扫码登录会重开本地缓存的活动会话，缺少明确的换码入口；已经加载的图片没有独立时钟保证及时隐藏。

使用既有执行器组件、独立临时目录及真实服务账号执行只读诊断，没有使用真实账号文件。第一次回调约 11.8 秒，可见候选只有一张；约 73 秒平台自动换了图片指纹，页面始终没有出现可见“二维码失效”文字。第二个全新上下文的初始图片指纹不同，未证实全站静态占位图。诊断仅记录指纹、可见性、尺寸与耗时，不记录二维码内容、token、完整 URL 或凭据。

## 修复

- 只读取当前可见、加载完成且尺寸有效的二维码；取消前置 `networkidle` 等待。新图片需稳定至少 500 毫秒，并在发送前复核当前图片。
- 每次轮询跟随可见图片内容变化；手动刷新后等待实际新图片。重复图片不增加版本，也不延长展示窗口。
- 抖音事件使用受控的 `refresh_after_seconds`，最长 45 秒，仅作为后台保守展示窗口，不宣称平台真实有效期。Node 再次校验数值并限制到 1–45 秒；其他平台原策略保留。
- 前端去掉错误的“有效至”，独立计时隐藏过旧图片；图片加载或状态读取失败时也隐藏，提供“重新获取二维码”。
- 手动换码先取消、等待旧会话终态，再创建新操作；扫码恰好成功时保留成功会话。旧会话、旧版本或旧操作的迟到响应不能覆盖新二维码。
- 没有自动提交作品，没有自动处理安全验证，也没有放宽账号互斥、认证或私有资源权限。
