# 历史教程更新任务

## 用户任务与交互依据

作者发现旧教程错误或工具变化，需要在原内容上继续加工，复用已有图片、原片和工程，并保留旧版本、历史周次和各平台发布链接。完成一次拍摄不能让内容退出可编辑、可搜索的内容库。

实现前在已运行的 Edge 窗口查看 [Contentful Versions](https://www.contentful.com/help/content-and-entries/versions/) 的[官方界面截图](https://images.ctfassets.net/aeu1amk9b600/104J6dSbzWqTMBjdFwJ73d/a10c9d1ae393137ba19b82469d74c566/image.png)：按时间排列版本，清楚标注状态，选中后查看。采用紧凑版本列表、独立创建弹窗及当前任务操作，保留本站 Radix、Lucide、语义 tokens 和明暗主题。

## 数据与使用边界

- 历史教程标题直接打开原正文；“创建更新”记录原因、更新范围与说明，沿用内容 slug/id，生成独立更新任务，默认加入待拍队首。
- 每个内容最多一条进行中的更新任务；重复请求幂等。普通排期条目和更新条目使用不同身份，同一教程不同轮次不互相覆盖。
- 创建时记录原工作稿/线上稿修订、选中成片和全部素材版本引用；完成时记录本轮结果。素材字节沿用现有不可变存储，不重复上传、不删除旧文件。
- 完成表示制作完成；保存、完成、取消不会自动发布。文章继续走固定预览版本确认，平台视频仍走原发布中心；新发布关联明确任务编号，旧记录保持原样。
- 取消保留任务及原版本，不回滚工作稿、不删除素材、不撤回平台作品。历史页和更新记录可以查看过去的轮次。
- 更新记录私有持久化于 `project/.content-updates/state.json`；原子写入、版本冲突、失败后排期同步恢复。排期 v3 保留旧条目与周次，不用旧备份覆盖新写入。
- 历史网站发布只显示有证据的记录；无法还原完整旧发布时间线时不推断日期。新发布逐次保存，平台记录保持各自实际状态。
