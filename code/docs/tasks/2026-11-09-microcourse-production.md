## 实现范围

- 复用内容工作区 UUID 和 slug。每条现有内容按需建立一份制作档案；不复制目录，不创建第二个标题来源。当前标题来自已有工作稿，草稿转网站内容保留同一身份。
- 新增“制作进度”列表和内容内“制作流程”页签。九步分别保存 Markdown 工作稿、不可变修订、检查、审阅决定及下一动作；支持比稿、阻塞、暂停恢复与交接导出。
- 制作数据库为私有项目 `.production-workflow/production.sqlite`，阶段及检查定义在建档时完整快照，以 SHA256 固定。升级代码不静默改变既有课程规则。
- 每次写入在 SQLite 事务内校验 rowVersion、幂等键及引用归属。重试先查原结果，不因旧 expectedVersion 重复创建；请求内容变化必须使用新键。文章或素材暂不可读取时，已提交的同一请求仍可恢复原结果。
- 关联媒体先核对现有私有素材的实际字节与摘要；文章使用既有不可变修订对象。相同源版本组、产物类型及发布版本复用稳定产物身份。媒体归 S08，文章归 S09，避免放错阶段漏过验收。
- 修改口播使对应音频、字幕、成片及依赖失效；历史检查和确认保留，当前有效性重新计算。不同平台当前视频分别验收。提交通过检查、确认版本及完成本期前，再核对相关实际文件。
- 原文章编辑器保存新标题后，只读观察会将旧标题绑定的制作稿、检查和确认显示为需复核，不修改 rowVersion；新的 S01 修订绑定真实新标题，并持久失效下游旧依据，防止旧确认复活。标题以现有文章为准，不允许客户端伪造标题快照。
- 连续制作授权与逐版确认分别记录。网页作者可确认明确修订；MCP 转述只记待核对反馈。自动检查不能代替实际音画播放；S08 必过项不能用不适用跳过。
- 后台提供同一业务服务的受限 MCP 适配，默认关闭，连接和部署边界见 [MCP 说明](../dev-guides/production-mcp.md)。本机已验证 OAuth → MCP 读取 → 阶段稿写入 → 原作者接口读回同版的真实 HTTP 往返；这不是正式 ChatGPT 安装验收。
