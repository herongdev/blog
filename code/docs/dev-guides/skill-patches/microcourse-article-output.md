# 开发者知识微课制作 Skill：配套文章输出规则

以下规则已于 2026-11-05 并入云端 [开发者知识微课制作 Skill](https://chatgpt.com/skills?skill_id=6ae410fcd95c8191838d8d12b8a17595) 第 5 节，并在保存后重新下载核对。原来的选题、讲解、分镜、视频、片尾和迭代要求完整保留；这里只记录本次配套文章增量规则。

## 交付一份可以直接导入的文章

配套文章交付 UTF-8 `.md` 文件，文件开头是 `---` 包裹的 YAML frontmatter，后面紧跟完整正文。提供下载文件；用户要求复制时，提供一份可完整复制的 Markdown，不把元数据留给发布者另外填写。

元数据与文章内容一起生成，修改文章时同步更新；正文不重复展示 YAML，不在文件中保留 TODO、REPLACE_WITH、示例来源或空的亲测结论。不得为了通过校验填造版本、测试日期、环境、截图结果或视频链接。

### 字段契约

| 字段 | 生成要求 |
| --- | --- |
| `title` | 对应本篇真实问题和收益，至少 8 字；可以与视频的吸引点击标题不同。 |
| `summary` | 至少 20 字，概括解决的问题、适用条件和结果范围。 |
| `tool` | 使用后台支持的工具 slug，不能直接写品牌显示名。 |
| `status` | 默认 `lead`，表示资料已整理但尚未完成实测；明确是中间草稿时用 `draft`。只有已有真实实测依据时才用 `published`，并填写 verification。此值是内容类型，不表示文章已经上线，传入后台始终仍是工作稿。 |
| `updatedAt` | 本次实际修改日期，`YYYY-MM-DD`，按 Asia/Shanghai；不能替代实测日期。 |
| `version` | 仅在依据明确时写实际核对的版本/适用范围；不知道就省略。 |
| `platform` | 写有依据的平台、设备、套餐或前置条件；不把推测写成已验证。可省略。 |
| `keywords` | 从本期内容提取真实关键词，字符串数组。 |
| `searchClues` | 至少 2 条观众可能记住的按钮名、口播说法或具体问题，字符串数组。 |
| `themes` | 仅填已支持且相关的主题 slug；无对应主题用 `[]`，不要临时编造目录。 |
| `featured` | 默认 `false`，不替作者决定首页重点推荐。 |
| `officialSources` | 至少 1 条实际核对的一手来源，每项为真实 title/url；文中具体结论有对应依据。无法取得可信来源时说明尚缺依据，不生成“可发布完成”的交付。 |
| `discoverySources` | 二手线索的真实 title/url，没有则 `[]`；不能冒充官方依据。 |
| `verification` | 仅已有真实实测时提供 testedAt、environment、result。testedAt 是实测发生日；environment 与 result 各至少 8 字，描述实际环境和可观察结果及限制。读过文档、通过构建、教学模拟和查看截图分别如实描述，不自动升级成已实测完整产品流程。无依据时整段省略，并在正文写清待实测范围。 |
| `videoUrl` | 仅关联已实际上线且对应本篇的视频地址；本地 MP4、待上传文件和演示链接不填。`lead` 不填写此字段。 |

当前支持的工具 slug：`codex`、`cursor`、`trae`、`vscode`、`github`、`git`、`chrome-devtools`、`claude-code`、`apifox`、`qoder-cn`、`codebuddy`、`zcode`、`ttok`、`remotion`。

当前主题 slug：`parallel-work`、`context`、`api-debugging`、`remote-work`。不适用就用空数组。后台未来调整时，以项目 `src/data/tools.ts`、`src/data/themes.ts`、`src/content.config.ts` 为准，不把本文件清单视为永远不变。

使用 canonical 字段 `summary`、`updatedAt`、`keywords`；不再默认输出旧格式 `description`、`date`、`updated`、`tags`。正文标题可以是 H1；文章地址由作者后台的内容身份负责，导入时不据 `slug` 覆盖其它内容。

## 审稿与资源

文章与视频保持事实、版本、术语和结论一致。先讲本期工作问题和收益，再给能照着做的操作、验证和限制；不为了凑模板给不存在的步骤、效果或实测结论。

交付前核对：YAML 可解析且没有重复键；日期是真实日历日期；工具/主题合法；声明为实测教程时验证记录完整；没有占位符；全文事实和引用对应。发现问题先修稿，再交付。

若使用本地图片、SVG、附件或视频，随文章交付完整资源包和相对路径清单，检查图片嵌套链接的两种目标。Markdown 粘贴/单文件导入只处理文字与元数据，不会自动把本地资源上传成公网 URL；在资源上传并替换引用前，不宣称图片和附件已经可用。保持外部来源链接原样，不把私有文件路径写成线上资源地址。

## 导入与未来直送

当前后台支持导入整份 Markdown 到当前工作稿：查看识别出的标题、工具、状态和缺项后确认应用，再预览、修稿、保存。导入不会自动发布网站或投稿视频，不改变当前文章的稳定身份。

未来增加插件直送时沿用同一份 Markdown：提交到有鉴权、只写草稿的入口，返回草稿身份、版本和检查结果；重复提交按幂等键更新同一份稿，旧版本冲突要回报。密钥由连接配置保管，不写进 Markdown 或 Skill；后端仍做独立校验。成功推送草稿与正式发布是两次独立操作。当前没有启用新的插件凭证或机器写入入口，不能承诺已可从任意 GPT 直接推送。
