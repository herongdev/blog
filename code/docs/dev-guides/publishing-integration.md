# 视频发布中心

## 边界与入口

发布中心属于 `apps/dev-guides/author` 教程写作台，复用微信管理员会话、Origin / CSRF 检查和现有 React / Radix / Lucide 体系。网站构建发布仍由原来的 `publish-manager.mjs` 负责。视频投稿、文章保存和网站上线是独立操作。

主工作区增加“发布中心”，内部包含“新建发布”“账号”“发布记录”。先建立平台账号并登录，上传或选择一个视频，编辑通用内容与各账号覆盖项，核对预览并明确提交。B站需要先在执行节点本地终端完成登录，再在页面检查账号。保存草稿、预检查和页面刷新不发布作品。

本期只接入抖音、小红书、视频号、B站的视频即时投稿。平台能力来自受控版本的 Python 执行器；真实账号验证结果单独记录，不因构建或模拟适配器测试通过而标为实测。

## 代码与进程

- `apps/dev-guides/author/src/PublishingCenter.tsx`：用户操作和状态展示。
- `apps/dev-guides/author/publishing/`：SQLite、私有素材、后台执行、受鉴权保护的 API。
- `integrations/social-publisher/`：独立 Python 环境、SAU fork 锁定、必要补丁和执行协议。
- `infra/dev-guides/author/`：宿主服务、可选执行器环境配置、上传代理和私有备份。

Node 只通过参数数组启动受信任的 Python 入口。浏览器传递内部素材与账号 ID，不能传 Cookie 路径、程序路径或命令。每个 Python 进程处理一个登录、检查或投稿操作；第一版整个执行器串行。验证码和提交授权从独立控制通道送入，不在执行队列后等待。

## 私有持久数据

生产默认位于 `/var/lib/herong-dev-guides-author/publishing/`，也可由服务端 `PUBLISHER_DATA_DIR` 指定；本地默认 `apps/dev-guides/.publishing-private/`，已从 Git、Vite 访问和部署包排除。

| 路径 | 内容 |
| --- | --- |
| `publishing.sqlite` | 账号、素材登记、发布批次、逐账号目标、执行尝试、登录会话与租约 |
| `assets/` | 私有成品视频和经过解码验证的封面 |
| `accounts/` | 执行器使用的账号会话，不通过 API 返回 |
| `runtime/` | 短期二维码与人工验证现场文件，完成或过期后清理 |

任务保存最终内容快照与素材摘要。素材没有自动删除或覆盖入口，避免运行中任务读到另一份文件。私有素材通过同源受鉴权接口预览，视频使用 Range 请求；二维码不进入公开媒体桶。

初次启动创建 SQLite schema v1；后续升级采用兼容迁移，禁止删除数据库来升级。原 Markdown、目录 JSON、拍摄排期与管理员身份不迁移。

## 提交与恢复

首期部署为一个 Node 实例、一个全局执行槽。数据库租约可阻止第二个实例同时领取，但验证码控制管道属于持有任务的进程；本期不支持负载均衡下的跨实例控制转发。

每个目标独立排队、执行和记录结果。提交幂等键避免请求重放创建重复执行。真正点击发布前，执行器必须取得后台持久确认；后台在同一事务中核对活动尝试、有效租约和取消状态。

“已提交平台”仅表示有平台受理证据，不能等同于审核通过或公开视频。“结果待核实”不会自动重发。提交后发生失联或崩溃时，先人工查看平台作品，再记录核对结果；只有确认未发布且旧进程已停止，才可重新尝试。

取消操作不会撤回平台作品。超时或取消后先停止子进程及其浏览器，再按提交边界记录结果。验证码不写入永久历史或日志。

## 本地运行与隔离验收

先按 `integrations/social-publisher/README.md` 准备独立 Python、锁定的 fork 和浏览器。不要使用系统 Python 3.9，也不要直接套用 SAU 历史 Web Dockerfile。

在 `code/` 中运行 `pnpm --filter @herong/dev-guides-author dev`。未配置执行器时可以进入模块、管理素材和草稿；登录和真正投稿必须等执行环境就绪，不显示虚假的发布结果。

执行器初始化完成后，在 `code/` 启动完整本地模式：

```sh
PUBLISHER_PYTHON="$PWD/integrations/social-publisher/.venv/bin/python" \
PUBLISHER_SAU_ROOT="$PWD/integrations/social-publisher/.vendor/social-auto-upload" \
pnpm --filter @herong/dev-guides-author dev
```

可用 `DEV_GUIDES_AUTHOR_PROJECT_ROOT` 指定开发数据副本，`PUBLISHER_DATA_DIR` 指定隔离的发布数据目录，`DEV_GUIDES_AUTHOR_PORT` 指定未占用的本机端口。此开发服务只监听回环地址，不通过公网代理暴露。

## 生产准备与回滚

以下是部署与回滚流程；2026-11-02 的实际上线记录见文末。现有教程后台地址及部署边界不变。执行器需要独立准备、锁定提交并在服务账号下验证，不从后台请求里自动安装依赖。

1. 备份现有作者数据；核对服务器磁盘、内存、Python 与浏览器系统依赖。
2. 按执行器文档安装到独立版本目录。根据实际路径设置 `publishing.env`，模板为 `infra/dev-guides/author/publishing.env.example`。私有数据放在服务账号可写目录；Python 与浏览器可执行文件随 `/opt` 中的执行器版本部署，避免作者安装器对数据目录递归设置 0600 时清除执行位。
3. 现有 service 读取可选 `publishing.env`。确认 systemd 的只读目录、任务数和内存限额能运行一个浏览器；不要关闭所有系统隔离来规避单项缺失。
4. 更新宿主代码、类型检查和构建。现有白名单部署脚本不会打包本机私有数据或依赖检出；Python 执行器独立安装。
5. Nginx 的大文件额度仅加在 `/admin/api/publishing/assets`，保留现有后台鉴权与其他接口的请求限额。校验配置后再 reload。
6. 验证未登录的素材、二维码、任务 API 为 401，私有目录不可公开访问；验证小视频上传、预览、刷新恢复及正常退出。
7. 由本人逐平台扫码；真实投稿只使用本人明确选择并确认的素材与账号。实际平台限制和未完成的人工验证如实记录。

备份脚本使用 SQLite backup API 生成一致快照，再保存素材与账号文件；SQLite 子进程以数据库所属服务账号运行，源连接保持 `mode=ro`，父进程保管 root 私有归档。WAL 数据库在停服后仍可能需要重建辅助文件，因此备份服务仅额外允许发布数据目录写入，不能把整个作者数据根开放写入；不复制正在变化的 DB/WAL 文件组，不保存临时二维码或浏览器缓存。需要完整恢复时先停止执行器和宿主，备份当前数据再恢复；恢复的未完成尝试仍须按提交边界核对，不能自动重发。

恢复旧数据备份与普通进程重启不同：备份中的 queued 任务可能已在备份之后实际投稿。恢复期间保持执行器禁用，确认所有原执行进程已停止，将恢复的 committed 批次中 queued/running/waiting_user 目标逐一转为待核实并核对真实平台，处理完成后再启用 worker；不能直接把历史队列重新跑一遍。

备份服务同样读取 `publishing.env` 的 `PUBLISHER_DATA_DIR`，归档内统一使用 `publishing/`。自定义路径时需同步核对两个服务的文件访问权限，尤其备份服务的 `ReadWritePaths` 必须对应实际发布目录，恢复到同一个配置目录。

回滚时先停止当前执行进程，再切换宿主和匹配的执行器版本，保留私有数据库、素材与账号会话。已经提交到第三方平台的作品不会因代码回滚撤回。
