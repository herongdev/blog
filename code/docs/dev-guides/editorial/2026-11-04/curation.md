## 保留标准

- 实际工作痛点：会造成错误、返工、交付受阻，不能只有“有这个按钮”。
- 可演示结果：失败或受阻状态、关键动作、可核验结果构成闭环。
- 信息增量：基础操作同样可以保留，关键是对目标观众有明确收益；不按新颖程度或技术难度排序。
- 重复与碎片化：同能力换品牌不再独立拍；完整任务的准备、入口和收尾不拆成配额。
- 实现门槛：优先现有工具、自写小项目、可信假数据；不为拍摄增加不必要的账号、服务与依赖。
- 证据：当前一手来源只支持机制；自己的版本、仓库、命令、录屏、结果另行实测。

“归档”不表示这些工具功能毫无用途，而是当前题目的独立视频价值、案例或证据不足，或可作为已有题的一步。基础入口也能保留：本地历史找回误改、部分暂存防夹带和实际请求定位都有清楚的工作收益。Git bisect 也不是因为更高级才保留，而是能给出可独立复核的回归提交证据。每条短片只需要讲清一个有收益的操作结果，不要求一分钟讲完长教程；完整环境、失败分支与验证细节可放文章。
