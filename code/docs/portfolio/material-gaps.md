# 个人官网材料缺口（内部）

本文件不在 VitePress `docs/` 发布目录内，仅用于后续补充作品材料。当前公开页面不使用占位图、不伪造数据，也不展示未经授权的企业内容。

## 建议优先补充

1. **公开联系方式**
   - 当前履历没有可公开的邮箱、电话或社交账号。
   - 如需让招聘方直接联系，建议提供一个专门的求职邮箱或经过确认的公开渠道。

2. **可下载简历**
   - 根目录现有 `简历.md` 是内容来源，但尚未确认可作为公开下载文件。
   - 建议提供经脱敏、排版和确认的 PDF，再在页头或关于页增加下载入口。

3. **真实项目截图或演示视频**
   - 当前仓库只有站点 Logo，没有可公开的项目 UI 截图。
   - 建议按项目提供桌面端和移动端真实截图；企业项目需先确认脱敏和公开授权。
   - 在材料补齐前，网站只使用明确标注的能力结构和文字证据。

4. **MiniCodex 代码仓库**
   - 站内旧文章引用的 GitHub 地址当前返回 404。
   - 若仓库重新公开，应先确认 URL、README、许可证和代码状态，再补充入口。

5. **企业项目的可公开证据**
   - 可考虑补充脱敏后的架构图、本人负责模块清单、公开验收材料或技术复盘。
   - 不建议上传真实客户数据、内部账号、地图敏感数据和未授权界面。

6. **项目结果指标**
   - 当前没有可核验的性能、用户量、转化或交付效率数据，因此公开页不写数字成果。
   - 后续如补充，需同时记录统计口径、时间范围和可公开依据。

## 发布前复核

- 联系方式是否明确授权公开。
- 简历是否完成脱敏并与网站经历一致。
- 项目截图是否为真实界面且具备公开权限。
- 外链、课程、产品站是否仍然可访问。
- 所有角色描述是否区分独立完成、负责人、核心开发和团队参与。
