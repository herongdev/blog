# UI 规范

适用于本站主页、博客主题及 `code/apps/` 下各子项目的用户界面。新增和修改 UI 时均须遵守。

## 图标

- **禁止使用字符充当图标。** 不得用 Unicode 箭头、数学符号、字母、Emoji 等替代操作、导航或状态图标，例如用 `↗` 表示外链、`×` 表示关闭、`☰` 表示菜单。
- **项目统一采用 Lucide。** 公开教程站与 Astro 主站使用 `@lucide/astro`，React 写作台、聊天及工具应用使用 `lucide-react`，Vue / VitePress 使用 `lucide-vue-next`。这些是同一套图标的框架组件，按名称按需导入，不通过字体字符、远程图标字体或整库动态查找渲染。
- 同一界面统一图标体系，保持线条粗细、尺寸和视觉风格一致。按需引入，避免仅为单个图标引入整套 UI 库。
- 不得用手写 SVG 路径、CSS 拼图或伪元素中的字符绕过上述规则；库提供的 SVG 图标可以正常使用。
- 纯图标按钮必须提供可访问名称（例如 `aria-label="关闭"`）；仅作装饰的图标使用 `aria-hidden="true"`，动作含义由文字或按钮名称表达。
- 正常正文标点、代码示例及文字品牌标识不属于图标替代；不得借此将操作图标继续写成字符。
- 本约定覆盖整个项目的公开页面、写作后台、目录树、弹窗、工具栏、空状态、移动端和明暗主题，也适用于后续新增页面。不能把 Emoji、首字母或特殊符号放在图标容器里充当临时实现。
- 图标继承 `currentColor`，使用统一的尺寸、描边与语义颜色 tokens；图标大小与按钮触控区域分别控制，不能为了图标紧凑而缩小触控目标。状态同时保留可读文字，不仅靠图标或颜色区分。
- Radix Primitives 负责无样式交互行为，Lucide 负责图标，两者搭配使用。ByteMD 等已有编辑组件自身提供的库图标可保留；新增或可配置的业务图标使用 Lucide，不修改 `node_modules`，不以 CSS 字符覆盖第三方工具栏。

### 常用语义与组件

| 界面用途 | Lucide 组件 |
| --- | --- |
| 新建目录、目录展开状态 | `FolderPlus`、`Folder`、`FolderOpen` |
| 文章、搜索 | `FileText`、`Search` |
| 展开、折叠、返回 | `ChevronRight`、`ChevronDown`、`ArrowLeft` |
| 新增、关闭、更多 | `Plus`、`X`、`MoreHorizontal` |
| 编辑、保存、删除 | `Pencil`、`Save`、`Trash2` |
| 外链、视频 | `ExternalLink`、`Play` |
| 加载、成功、提醒 | `LoaderCircle`、`Check`、`CircleAlert` |
| 明暗主题 | `Sun`、`Moon` |

例如 React 中使用 `import { X } from 'lucide-react'`，在有 `aria-label="关闭"` 的按钮内渲染 `<X aria-hidden="true" />`；Astro 使用 `import { X } from '@lucide/astro'`。图标表达的含义相同时复用相同组件，不用相似字符或另一套图标临时替代。

### 验收

- 检查模板、JSX 和 CSS `content`，确保没有字符式操作、导航、状态图标。
- 检查图标是否来自选定库，尺寸、对齐和深浅色表现是否一致。
- 检查纯图标按钮的可访问名称和键盘焦点。
- 检查动态生成的 DOM、空状态、第三方组件扩展项及移动端；正文中的 Markdown 语法、步骤编号、命令和标点不做机械替换。

## 响应式与 H5

- Astro 主站的适配规则与语义变量位于 `apps/site/src/styles/site.css`，共享项目概念图样式位于 `apps/site/src/styles/project-visuals.css`。VitePress 历史文章和完整兼容站继续使用 `apps/blog/docs/.vitepress/theme/responsive.css`。修改共享 Vue 概念图时须检查两种构建，不通过给整个页面设置 `overflow: hidden` 掩盖布局溢出。
- 支持 320px 起的手机、平板、桌面及超宽屏；首页三列 / 两列切换。宽屏内容最大 1440px，正文沿用阅读宽度，不随屏幕无限拉伸。
- 内容内页在矮屏允许纵向滚动，不裁切信息。首页按用户最新要求一屏展示，采用弹性封面与紧凑双列布局，具体规则见 `homepage.md`。手机横屏菜单自身可滚动。
- 导航和主题按钮至少 44px 触控区域；移动菜单至少 48px 行高，支持 Escape 关闭和键盘焦点。
- 保留刘海、横屏侧边与底部安全区。不能禁用用户缩放。
- 长标题、链接正常换行；代码块和宽表格在自身内部横向滚动，不撑宽页面。
- 修改共享样式后，检查首页、分类、项目详情、文章列表、教程正文、自营产品和关于；覆盖 320、390、600、768、1024、1440、2560px，以及 844×390 横屏。检查深浅色、导航开关、页面溢出和实际截图；浏览器模拟不能代替 iOS/Android 真机验收。

## 项目落地

- 主站 `apps/site/` 使用 Astro 7 + TypeScript 静态生成，Astro 模板图标使用 `@lucide/astro`。主要文字、导航和作品链接保留在初始 HTML；已有 `FieldPreview.vue` / `ProjectVisual.vue` 通过 `@astrojs/vue` 在构建时渲染，只有需要状态的区域加载 Vue 交互岛，当前为首页背景。不要把整个主站改成单页应用或 `client:only`。
- 主站主题与移动导航使用语义化 HTML、原生按钮 / `details` 和少量 JavaScript；Escape 关闭移动菜单后焦点返回入口。主题优先读取 `vitepress-theme-appearance`，兼容 `herong-theme`，切换时同步两者，保留 `auto` 跟随系统。
- VitePress 文章兼容主题继续使用 `lucide-vue-next`，外链、菜单、关闭、主题切换通过组件引用。
- 3D 展示使用 `lucide-react`，HUD 图标在 `HudIcons.tsx` 中集中映射。
- 聊天应用、工具箱沿用已有 `lucide-react`。
- 检查范围包括未挂载的旧组件、移动导航和 CSS 伪元素。图表与地图绘图、品牌标识、正文符号和测试数据不作为操作图标替换。

## 开发工具教程子站：headless UI 约定

本节约束 `code/apps/dev-guides/` 的**公开网站**。公开页面当前使用 **Astro 7 + TypeScript + 静态 HTML + 少量原生 JavaScript**，尚未安装 React 或 UI 组件库。`author/` 写作台是独立的 React 19 + ByteMD 应用，支持本机模式及登录保护的线上模式，并复用本站 tokens；它单独部署，不进入公开教程站点构建。作品主站 `apps/site/` 使用 Astro + 按需 Vue 交互岛，历史文章 `apps/blog/` 保留 VitePress + Vue；它们与本教程公开站是独立应用，不能因共享 Astro 或参考 Vue 官网主题开关的外观，就把教程子站误写成 Vue 项目。本节的 React / Radix 约定保持不变。

- **指定库：Radix Primitives（无样式组件），配 React 19 交互岛。** 出现弹窗、弹出菜单、组合选择、提示气泡等需要焦点管理和键盘交互的组件时，在 Astro 中通过 `@astrojs/react` 按需挂载 React 组件，优先使用 Radix Primitives 的对应原语；不要把整个静态站改造成单页应用。第一次实际使用时再加入依赖，先实现并验证一个真实组件。仅有选型约定不代表当前站点已经集成该库。
- 普通链接、按钮、搜索框、表单标签和简单单选筛选使用语义化 HTML。现有工具筛选的原生 radio 已满足需求，不为满足库覆盖率而替换。需要自绘弹出选单时使用 Radix 的 Select/Popover 等原语，不自行拼接角色、焦点和键盘逻辑。
- Radix 只提供行为和可访问性基础；外观统一引用 `src/styles/tokens.css` 的语义变量，覆盖浅色、深色、悬停、选中、禁用、焦点、触屏和窄屏状态。不要引入 Radix Themes 或另一套视觉主题。Astro 模板的图标沿用 `@lucide/astro`，React 交互岛需要图标时使用同一 Lucide 图标体系。
- React 交互岛只在确有客户端状态的区域使用；教程正文、导航链接和搜索可索引文本保持 Astro 服务端生成的 HTML。组件上线前检查键盘操作、读屏名称、焦点回收、Escape 关闭、触控目标、亮暗主题和 320px 宽度。

选型依据：[Astro 的 React 集成](https://docs.astro.build/en/guides/integrations-guide/react/)支持在 Astro 页面中按需渲染和激活组件；[Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction)提供无样式、可逐步采用的 React 原语。用户提出的 [Zag.js](https://zagjs.com/) 是跨框架的底层状态机，需要自行接线到组件；当前子站以 React 作为未来交互层，因此采用 Radix 作为统一组件接口。

## 公开教程站：浏览与搜索

- 读者的任务是凭记得的时间、工具或功能找回完整内容。搜索始终可见；“按周 / 按主题 / 按工具”是同一批内容的不同浏览入口，用普通链接切换，不增加介绍口号或重复内容系统。首页默认按周展示近期教程，完整周目录在 `/weeks/`，主题在 `/themes/`，工具在 `/tools/`；文章地址仍为 `/topics/<slug>/`。
- 周标题显示真实日期范围，按 Asia/Shanghai 的周一至周日归档首次正式发布的教程；不使用拍摄计划、目录名称或最后更新日期推断。没有可靠首发日期的旧教程放在“往期教程”，不虚构归档周。没有已发布教程时显示真实空状态，功能资料另列并标明“尚未实测”。
- 一套搜索同时支持关键词、工具、主题和发布周，URL 使用 `q/tool/theme/week` 保存条件；页面路径表示浏览位置。刷新和前进后退恢复条件，清除后恢复原目录。搜索结果出现时隐藏原浏览列表，避免两套相互冲突的筛选和计数。
- 搜索显示实际总数及已显示数量，超过 12 条提供“加载更多”；加载失败提供重试。主题和发布周放在“更多筛选”内，选中数量可见；键盘、长标签、窄屏及无匹配状态都必须可用。
- 教程标题直接进入正文；只有存在真实视频地址时才提供独立“观看视频”入口。列表、正文、搜索结果保持相同状态含义；私有草稿和后台排期不能进入公开目录或索引。各目录及正文保留静态 HTML 链接，搜索脚本失效时仍可浏览。
- 视觉延续 tokens、明暗主题和 Lucide；当前普通链接、搜索、单选组与原生 `details` 已满足交互需求，不为三个浏览入口额外引入客户端框架。

## 教程写作台：目录与编辑工作区

本节约束 `apps/dev-guides/author/`，与上一节的公开静态站分开。写作台使用 React 19、ByteMD 和 **Radix Primitives**：目录操作弹窗用 `@radix-ui/react-dialog`，节点操作菜单用 `@radix-ui/react-dropdown-menu`，目录选择用 `@radix-ui/react-select`。这些依赖已用于作者前端实现；线上生效版本以部署记录为准。不得引入 Radix Themes 或复制另一项目的整套视觉组件来替代无样式原语。

- 工作区服务“找到文章、组织目录、继续编辑”：桌面左侧为稳定宽度的递归目录导航，右侧为弹性编辑区，避免把整套工作台限制在居中的正文阅读宽度。公开教程正文仍沿用自己的阅读宽度。
- 目录使用稳定 ID，保留展开和选中状态。支持新建目录和子目录、重命名、选择目标位置移动、删除空目录；文章也可移动到指定目录或“未分类”。新建草稿归入当前选中目录。移动和重命名目录不改变文章地址；删除入口必须说明非空目录需先移走内容，不能递归删除文章。
- 搜索支持目录名、文章标题和文章地址；命中深层内容时保留祖先路径并展开，搜索期间不能因“未分类”筛选隐藏匹配目录。目录选中态与当前编辑文章的高亮应可区分。
- 导航使用嵌套列表及具有名称的原生按钮，展开按钮提供 `aria-expanded`；没有实现完整树键盘协议时，不添加误导性的 `role="tree"`。节点操作使用 Lucide 图标，不能只依赖悬停才可发现或操作。
- Radix 菜单打开弹窗时避免菜单关闭回焦抢走弹窗焦点。弹窗支持 Enter 提交、Escape 关闭；关闭后回到原触发按钮，节点已删除时回到稳定的目录入口。提交期间防止重复操作；失败保留输入，版本冲突刷新目录并提示重试，不能刷新或覆盖未保存的正文。
- 外观继续引用 `apps/dev-guides/src/styles/tokens.css` 的语义配色、排版、间距、圆角和焦点变量；作者专属尺寸及层级变量集中于 `author/src/styles.css`、`author/src/library.css` 的 `--author-*` 声明。新增样式同时覆盖明暗主题、选中、悬停、禁用和焦点状态。
- ByteMD 默认 CSS 只在 `author/src/main.tsx` 中、本站样式之前加载一次；不要放回懒加载编辑器中，避免后到的默认样式覆盖主题。工具栏、状态栏、下拉层、侧栏、代码与预览统一使用语义颜色，深色主题不能残留白底低对比控件。
- 760px 及以下使用“文章 / 编辑”切换，编辑器采用单栏编辑与预览标签；长标题和摘要随内容及窗口宽度调整高度。目录、菜单、弹窗和选择器在 320px 宽度可用，手机操作目标至少 44px；代码和表格仅在自身内部滚动，不用全页裁切掩盖溢出。
- 验收覆盖明暗主题、桌面和窄屏、长标题及多级目录、搜索命中祖先、在选中目录新建草稿、移动后刷新持久化、非空删除拦截、弹窗焦点返回与多窗口版本冲突。组织目录时必须保留当前未保存稿；浏览器模拟不等于手机真机验收。

## 教程写作台：拍摄排期

- 作者的主要任务是决定“这两周拍什么、临时题放哪里、下一条写什么”。工作区区分“拍摄排期”和“文章写作”，切换时保留未保存的正文。目录负责分类，拍摄先后由独立队列决定；原研究文件中的周序仅作初始顺序参考。
- 默认每周 3 条，自动安排范围固定为本周和下周。队列前若干条组成下周预览，其余只显示队列位置，不计算或展示第 3 周以后的日期。每周条数修改从下周生效，本周与历史不随之重排。
- 本周支持换序、标记已拍、撤销已拍、插入临时题及退回队列；已拍状态和网站发布状态是两个独立概念。临时插入可以超过本周数量目标，不自动挤走正在制作的内容。
- 队列提供分页、标题搜索、上移/下移、置顶、移到指定全局位置，以及独立手柄拖动当前页；使用 dnd-kit 的无样式排序能力，保留触控和键盘操作。筛选后不允许用局部索引重排全队列；跨页移动仍以全局位置为准。所有动作图标使用 Lucide。
- 新建临时素材只需标题，自动生成文章地址，可加入队首或队尾。创建成功但入队失败时明确显示结果，重试只执行入队。添加已有文章不复制正文，移出队列不删除文章。
- 周界采用 Asia/Shanghai 的周一。进入新周时，已预览的下周成为本周；上一周未拍项目按原顺序回到余下队列前部，历史保留未拍状态。长时间未打开后台只归档真实排过的周，不补造历史周或完成记录。
- 队列采用版本冲突保护，失败保留当前操作输入并提示刷新。历史保存当时标题，标题修改或稿件缺失不改写过去；缺失稿件不提供无效写作入口。排期、目录和文章分开持久化，均不可作为公开站静态资源。
