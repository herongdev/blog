核心设计要点（事实层，给你写简历做依据）：

1. **三层复用：composable → 字段组件 → 管理器组件**
- `useRange` / `useEntryPrice` / `useBasePrice` / `usePLPreview` 是 4 个纯逻辑 composable，可独立测试与组合。
- `SLTPField` 是受控字段（开关 + 数值输入 + 单位选择 + 实时提示）。
- `SLTPManager` 把 TP + SL 两个 `SLTPField` 合成一组，统一禁用/清空/恢复策略。
- 复用面：`SLTPManager` 至少在 **3 处** 复用 —— 交易面板的市价区 (`TradePanel.vue:65`)、限价区 (`TradePanel.vue:177`)、已成交单改 SL/TP 弹窗 (`SLTPTabPane.vue`)、挂单改 SL/TP 弹窗 (`PendingSLTPTabPane.vue`)。

2. **基准价/入场价分离**
- `useEntryPrice` 决定"成交价"：buy 取 ask、sell 取 bid，限价单允许 explicit 覆盖。
- `useBasePrice` 决定"风控基准价"（用对侧价做 stop level 校验），同样允许 explicit 覆盖。
- 这是经纪商业务里特别容易写错的一处，分开两个 composable 让语义不互相污染。

3. **动态范围提示按"四象限"自动推算**
- `useRange` 用 `direction = tradeDirection * exitType` 把 buy/sell × TP/SL 的 4 种方向折叠为 ±1，分别给出：
- `priceRange = { min, max, step, precision, suggestValue }`
- `pointRange = { min, max, step, precision, suggestValue }`
- `step`/`precision` 由品种 `digits` 推导（`10^-digits`），`min` 由券商 `stop_level` 推导，`suggestValue = stopLevel + 100 点` 是默认填入的"开箱即成交"建议值。
- UI 上 `rangeTip` 动态合成提示，例如 `\>100 points \>= 1.23540 \<= 1.24000`，随报价/方向/品种实时变化。

4. **价格 ↔ 点数 双向同步且 modelValue 唯一权威**
- `SLTPField` 内的 `displayValue` 用一对 `computed` 的 `get/set` 把 UI 显示在两种单位间换算，但 `modelValue` 永远保持"价格"语义对外暴露。
- 换算逻辑 `convertValueOnModeChange()` 抽到 `index.ts` 中作为纯函数，可单独单测。

5. **实时盈亏 4 口径预览**
- `usePLPreview` 同时算出 `points / money / percent / sign`，支持 `EQUITY` 和 `PRICE` 两种百分比口径。
- 全程 `Decimal.js` 计算，避免外汇 5 位小数 × 合约规模 × lots 的浮点累积误差。
- UI 提示语按 `valueMode` 切换两种排版："点数 \| 金额币种 \| 百分比" 或 "价格 \| 金额币种 \| 百分比"。

6. **延迟实例化 + 资源开关**
- `SLTPField` 用 `LazyScope` 的 factory 模式：只有在 `enabled && hasQuote` 时才创建 `useRange/usePLPreview` 实例，关闭开关或断流时停止订阅式计算，省 watch/computed 资源。

7. **业务校验闭环**
- `SLTPManager` 监听 `hasQuote` + `ask/bid` 有效性，自动禁用并记忆 enabled，恢复后还原；切换品种/方向时清空旧值，把"脏状态"的可能性降到 0。
- 错误信息走 `v-model:errorMessages`，i18n key 化（`components.numericInput.errors.*`），统一汇总到外层表单。

## 三、可以直接放进简历的两段

### 1）追加到「技术亮点扫描」中（你之前那个分析的格式）

【技术亮点 14 · 自研止盈止损（SL/TP）输入体系】

- **文件位置**：
- `src/components/sltp-manager/SLTPManager.vue`
- `src/components/SLTP-field/SLTPField.vue`、`src/components/SLTP-field/index.ts`
- `src/views/(public)/trading/_composables/useRange.ts`
- `src/views/(public)/trading/_composables/usePLPreview.ts`
- `src/views/(public)/trading/_composables/useEntryPrice.ts`、`useBasePrice.ts`
- `src/views/(public)/trading/_utils/sltp.ts`
- **实现内容**：
- 把"基准价 / 入场价 / 取值范围 / 盈亏预览"四件事拆成 4 个独立 composable，再用 `SLTPField`（字段级）+ `SLTPManager`（组级）两层组件做 UI 封装；
- 用 `direction = tradeDirection × exitType` 把 buy/sell × TP/SL 的 4 种方向折叠成 ±1，自动推导出"价格"和"点数"两套 range（min/max/step/precision/suggestValue），按品种 `digits` 自动配齐精度；
- 输入框支持「价格 ↔ 点数」双向换算，但对外 `modelValue` 始终是价格语义，保证上层表单/接口侧只看一种数据；换算逻辑抽离为纯函数，可独立单测；
- 输入时实时给出 4 口径预览（点数 / 金额 / 百分比 / 反向价位），全部 Decimal.js 精算；
- 用 `LazyScope` factory 模式，仅在开关开启且有报价时才实例化 range / PnL controller，关闭即停订阅；
- 自动联动业务规则：报价缺失或 ask/bid 为 0 时静默禁用、记忆 enabled 状态，恢复后还原；切换品种或交易方向时清空旧值，杜绝脏状态。
- **技术栈**：Vue 3 Composition API、`defineModel`、`MaybeRefOrGetter`/`toValue`、Decimal.js、Ant Design Vue、TypeScript。
- **业务价值**：止盈止损是经纪商交易最容易出错、也最影响真金白银的一处。整套设计把"业务规则（stop level、四象限方向、基准价/入场价分离）+ 数值精度（Decimal）+ UI 形态（双单位、实时预览）+ 复用（3 个使用点共用同一套 controller）"沉淀成一组可复用积木，新增挂单类型 / 移动端形态时几乎零改动。
- **简历建议表述**：
\> 自研基于 Composition API 的止盈止损输入体系：把基准价、取值范围、盈亏预览、价格-点数换算等业务规则拆解为 4 个独立 composable，再以「字段组件 + 管理器组件」两层封装；通过 `direction = tradeDirection × exitType` 折叠 buy/sell × TP/SL 四象限，按品种 `digits`、券商 `stop_level` 动态推导 price/point 双轨 range 与建议值，输入框双单位实时换算且对外保持价格语义唯一权威；全程 Decimal.js 精算并实时输出"点数 / 金额 / 百分比 / 价位"4 口径预览。**该体系在交易面板（市价 + 限价）和持仓 / 挂单改单弹窗等 4 个入口共用一份控制器**，新增 SL/TP 入口零改造。
