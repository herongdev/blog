# 优化

> 本节目标：理解“优化”的核心思路，并能把它用于实际开发或面试表达。
在你的组件中，你用 `computed` 和 `watch` 同时对路由变化作出响应，这种情况下确实有可能出现冗余的计算和响应。这通常取决于它们的具体实现和你的需求。

1. **`computed` 属性**：是基于它们的依赖进行缓存的，仅在其依赖发生变化时才重新计算。在你的情况下，如果 `computed` 属性用于从 Vuex store 中获取当前路由对应的菜单项，并且这个值是依赖于 Vuex state 中的路由状态，那么这是有效和高效的，因为只有在路由状态发生变化时才会重新计算。

2. **`watch` 属性**：可以监听 Vue 实例上的响应式数据（如 `$route`）的变化，并在变化时执行回调函数。这是处理异步或开销较大的响应式数据变化的好方法。在你的情况下，你使用了 `watch` 来响应路由变化并设置菜单状态。

如果两者都在监听 `$route` 对象的变化，并且在变化时执行类似的操作（如设置菜单激活状态），那么确实可能存在一些重复。在这种情况下，你可以考虑以下优化：

- 只使用 `watch` 来响应路由变化并设置菜单状态。这样可以保证无论何时路由变化，相关逻辑都会执行。
- 使用 `computed` 属性来定义菜单的激活状态，基于当前的 `$route`。然后在模板中直接绑定这个 `computed` 属性。

优化后，你的代码可能会看起来是这样的：
computed: \{
activeIndex() \{
// 依据当前路由来计算哪个菜单项应该激活
// 这个函数应该返回一个字符串或者数字索引，对应你的菜单项的标识符
const routePath = this.$route.path;
// 这里的 findMenuItemIndex 是一个假设的函数，你需要实现它来找到当前路由对应的菜单项索引
return this.findMenuItemIndex(routePath);
\},
// ... 其他的 computed 属性
\},
methods: \{
findMenuItemIndex(routePath) \{
// 根据 routePath 来查找菜单项索引的逻辑
// ...
\},
// ... 其他的 methods
\}

然后，在你的模板中，你可以这样绑定 `activeIndex`：
\<el-menu :default-active="activeIndex"\>
\<!-- 菜单项 --\>
\</el-menu\>

这样做，只要 `$route` 发生变化，`activeIndex` 计算属性就会重新计算，从而保证菜单项的激活状态总是正确的。

请注意，确切的解决方案取决于具体的业务逻辑和状态管理。在删除或合并重复的逻辑时，确保彻底测试以确保应用的功能不会受到影响。
