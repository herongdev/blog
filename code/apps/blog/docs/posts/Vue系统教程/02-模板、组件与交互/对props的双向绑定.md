# 对props的双向绑定

> 本节目标：理解“对props的双向绑定”的核心思路，并能把它用于实际开发或面试表达。
双向绑定也就是`v-model`的值必须是以下值之一：

- `reactive`值`;`
- `ref`值`;`
- 有`get`和`set`方法的计算属性；计算属性的依赖基不能由`props`，否则我们在`set`方法中就必须修改`props`值，这与`props`单身流动相冲突；但如果这个值确实和`props`值相关，我们应该是由`props`直接在`create`阶段计算得到一个`reactive`或`ref`值，这个计算属性`get`中的依赖值是这个`reactive`或`ref`值。
- 总之就是一个可以修改的响应式值；

`Props`的值有时我们不止是用于展示，我们还想对它进行修改；
比如在表单元素中；

如果`props`的某个属性值是对象或数组类型；
我们在组件中想修改它的元素；

如果将`props.propsName`直接进行赋值，`vue`会提示不许可，保持`props`的单向流动；
但如果我们只是修改`propName`这个对象的属性，`vue`目前是许可的，但并不推荐，除非它们是强耦合的；

**数组**
如果属性值是一个数组，我们要对数组进行增删改；

- 这个时候，应该根据属性值返回一个新数组，注意不是通过计算属性实现；
- 根据属性值得到的计算属性是无法修改的，没法双向绑定；
- 以这个新数组为初始值，定义一个`state`或`ref`值，这样，我们就可以对这个值进行修改了，并做到双向绑定；
- 并且不会修改`props`原数组；但如果数组的元素是一个对象，我们修改它的属性值，也会间接影响到原`props`数组；
- 如果`props`数组发生改变，由于不是响应式的，由`props`创建新数组的过程只在`setup`中发生，`props`变化时不会发生，所以我们`state`或`ref`的值并不再受`props`影响；
- 接下来，我们对计算得来的`State`或`ref`值进行双向绑定，或者进一步，可根据需要，由`state`或`ref`得到一个计算属性，对这个计算属性进行双向绑定；
- 总结来说就是，`props`直接计算一个`State`或`ref`值，对这个值进行双向绑定；或由这个计算出的`state`或`ref`值得出一个计算属性，对这个计算属性进行双向绑定；

这就是官网说的，由根据`props`定义一个计算属性；
所不同的时，如果是计算属性，`props`变化，计算属性值也会变化；
并且，我们无法对这个计算属性值进行修改；从而也不会修改`props`，但这无法满足业务中对`props`值要进行修改的场景；
