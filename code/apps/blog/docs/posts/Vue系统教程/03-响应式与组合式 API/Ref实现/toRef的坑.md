# toRef的坑

> 本节目标：理解“toRef的坑”的核心思路，并能把它用于实际开发或面试表达。
我们从一个响应像上取一个属性的值，用在我们的组件中的时候；
可以使用`toRef`来将这个属性值转化为一个`Ref`，就算该属性在对象上不存在时，也可以保持响应性；

但`toRef`只是做了一个取值和设置值的代理；
如果`toRef`的值并没有用到`effect`中的话，就算属性值变化了，也会失去响应，比如：

- 在模板中使用时，元素使用了`v-if`懒渲染，且初始状态不渲染
- 虽然用在了计算属性中，但计算属性在模板中同样是用在了`v-if`的元素中且初始不渲染；
- 或者用在了计算属性中

此时，应该使用计算属性来取代`toRef`来从对象上取属性值，且让它保持响应性，并且：

- 计算属性还可以设备属性值不存在时的默认值；
- 还可以进行复杂的计算和其它处理；
