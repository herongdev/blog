# mitt 和 vuex 怎么选择

> 本节目标：理解“mitt 和 vuex 怎么选择”的核心思路，并能把它用于实际开发或面试表达。
mitt和Vuex都可以用于在Vue.js应用中实现组件间的通信和状态管理。但它们有不同的适用场景和优缺点，你可以根据实际需求和应用的复杂度来选择适合的解决方案。

mitt

mitt是一个轻量级的、简单易用的事件总线库，适用于以下场景：

当你需要在组件间进行简单的通信时，例如广播一个事件或执行一次性操作。
当你的应用规模较小或只需要处理少量的全局状态时。
当你希望避免引入更复杂的状态管理库，以减小应用的体积和复杂度时。

Vuex

Vuex是一个专为Vue.js应用程序设计的状态管理库，适用于以下场景：

当你需要在组件间共享多个全局状态时，Vuex提供了一个集中式的状态存储和管理，使状态的变更更易于追踪和调试。
当你的应用规模较大或需要处理多个复杂交互时，Vuex可以帮助你更好地组织和管理应用的状态。
当你需要处理异步操作，如API调用、延时操作等时，Vuex提供了对异步操作的支持，使其更容易集成到应用中。
当你希望利用Vue DevTools插件进行状态管理的调试时，Vuex与Vue DevTools的集成可以帮助你更容易地跟踪和调试状态变更。
如何选择？

如果你的应用规模较小，只需要进行简单的组件间通信和少量全局状态管理，那么使用mitt可能是一个更轻量级的选择。
如果你的应用规模较大，需要处理多个复杂的状态和组件间交互，那么使用Vuex可能更适合你，因为它提供了更强大的状态管理功能和更好的可维护性。
你还可以根据实际需求结合使用mitt和Vuex，例如使用mitt进行组件间的简单通信，而使用Vuex来管理全局状态和处理复杂的应用逻辑。
