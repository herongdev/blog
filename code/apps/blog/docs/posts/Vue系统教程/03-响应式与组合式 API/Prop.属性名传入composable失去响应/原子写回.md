# 原子写回

> 本节目标：理解“原子写回”的核心思路，并能把它用于实际开发或面试表达。
**“原子写回”指的是：当子组件需要把变更同步给父组件时，通过唯一且明确的一次写入动作把“完整的新值”提交回去，而不是在子组件里分散地、逐字段地、悄悄地修改原对象**。
换句话说——**只走一条写回通道，一次性提交**；不在多处“边读边改”。
为什么要这样做：

- **可追踪**：父组件只需要监听一次“值被更新”的事件/模型写入，就能拿到**变更后的整值**，方便日志、校验、撤销/重做。
- **一致性**：避免“深层属性已被改，但父级并不知道”的脏改；也避免多次小改造成的中间不一致状态。
- **性能与语义清晰**：一次提交、一次渲染；变更语义更清楚（“我提交了一个新的 X”），而不是“我可能改了某些内层字段”。
- **兼容响应式系统**：Vue 更擅长捕获“引用变化”或“显式 set/emit”的信号；深改原对象常让依赖方**无法正确感知**或产生**时序问题**。

对比两种思路（只讲原则，不给代码）：

- ❌ **深改**：在子组件里直接改 props.modelValue.xxx = ...。这是**隐式、多处、不可控**的；父级很难集中感知。
- ✅ **原子写回**：在交互完成或阈值达成时，**基于旧值拷贝/计算出一个“新值”**，通过**唯一的写回入口**（如 v-model 的 setter / update:modelValue / defineModel 返回的 ref 赋值）**一次性提交**。

应用场景举例（抽象表述）：

- **表单草稿**：用户在子组件里编辑多个字段时，子组件内部先维护草稿；点击“保存”时，**一次写回**完整的表单对象。
- **输入法/节流**：输入过程在本地缓冲，结束/节流点到了再**一次写回**，避免把中间态频繁抛给父级。
- **复杂派生**：需要根据多个输入合成一个新值时，合成完成后**一次写回**，保证父级拿到的是**成品**而非半成品。

一句话总结：**原子写回 = 单一通道 + 一次提交完整新值**。这样能让数据流清晰、可控、可回溯，并与 Vue 的响应式与 v-model/defineModel 设计天然对齐。
