# 解析对象为什么失去响应

> 本节目标：理解“解析对象为什么失去响应”的核心思路，并能把它用于实际开发或面试表达。
在 Vue 中，props 的响应性是通过 Vue 的响应性系统实现的。这个系统基于 JavaScript 的 `Proxy` 对象和观察者模式来跟踪数据的变化。当你解构 props 时，会失去这种响应性。这是因为解构操作只是一次性的赋值，不会继续跟踪 props 的变化。下面是详细的解释：

### Vue 的响应性系统

1. **初始化**：当你定义一个组件时，Vue 会对组件的 props 进行初始化。这些 props 是响应式的，也就是说，Vue 会跟踪这些数据的变化，并在数据变化时重新渲染组件。

2. **`Proxy` 对象**：Vue 使用 JavaScript 的 `Proxy` 对象来实现响应性。`Proxy` 对象允许 Vue 拦截对象的操作（如读取、写入、删除属性等），从而实现对数据变化的跟踪。

3. **依赖收集**：当组件在渲染过程中访问 props 时，Vue 的响应性系统会记录这些访问操作。这称为依赖收集。每当这些依赖的数据发生变化时，Vue 会触发相应的更新操作。

### 解构导致失去响应性
当你使用解构赋值时，实际上是将 props 中的属性值赋值给新的局部变量。这些局部变量是普通的变量，不再受 Vue 响应性系统的控制。因此，解构 props 会导致失去响应性。

```javascript
// 这是响应式的 props
const props = { message: 'Hello' };

// 解构赋值
const { message } = props;

// 现在，message 是一个普通的局部变量，不是响应式的
```

### 底层原理
1. **代理对象的解构**：在 Vue 中，props 是通过 `Proxy` 对象实现的响应性。当你解构 props 时，你只是将代理对象中的值提取出来，而这些值本身并不是响应式的。

2. **失去依赖追踪**：解构后的变量不再是原始代理对象的一部分，因此 Vue 无法追踪这些变量的变化。这意味着当 props 发生变化时，解构后的变量不会自动更新。

### 示例

以下是一个简单的示例，说明解构 props 导致失去响应性的问题：

```vue
<template>
<div>
<p>{{ message }}</p>
</div>
</template>

<script>
export default {
props: {
message: String
},
created() {
// 直接使用 props.message 是响应式的
console.log(this.message); // 输出 "Hello"

// 解构赋值会失去响应性
const { message } = this.$props;
console.log(message); // 输出 "Hello"   // 更改 props.message 后，this.message 会更新，但解构后的 message 不会更新
this.$props.message = 'World';
console.log(this.message); // 输出 "World"
console.log(message); // 仍然输出 "Hello"
}
}
</script>
```

在这个示例中，`this.message` 是响应式的，当 `this.$props.message` 改变时，`this.message` 也会更新。但解构后的 `message` 只是一个普通变量，不会随 `this.$props.message` 的变化而更新。

### 总结

在 Vue 中解构 props 会失去响应性，因为解构操作只是一次性的赋值，不会继续跟踪 props 的变化。这是因为解构后的变量不再受 Vue 响应性系统的控制，不再是 `Proxy` 对象的一部分。因此，在 Vue 中使用 props 时，应避免解构赋值，直接使用 props 对象中的属性以保持响应性。
