# 运行计时器

> 本节目标：理解“运行计时器”的核心思路，并能把它用于实际开发或面试表达。
let ticksInterval
self.addEventListener('message', function (ev) \{
  const handlers = \{
    startTicks: (data) =\> \{
      ticksInterval = setInterval(() =\> \{
        self.postMessage(\{ type: 'tick' \})
      \}, data.delay)
    \},
    stopTicks: () =\> \{
      clearInterval(ticksInterval)
    \}
  \}
  if (handlers[ev.data.type]) \{
    handlers[ev.data.type](ev.data)
  \}
\}, false);

这段代码是一个运行在 **Web Worker** 环境中的 JavaScript 脚本，用于管理一个定时器（setInterval），并通过 postMessage API 与主线程通信。
概述
该代码运行在一个 **Web Worker** 中，Web Worker 是 JavaScript 提供的一种机制，允许脚本在后台线程运行，避免阻塞主线程的界面操作。代码的功能是：

1. 监听主线程发送的消息（通过 postMessage）。
2. 根据消息类型执行操作：启动或停止一个定时器。
3. 定时器通过 setInterval 定期向主线程发送“tick”消息。

代码使用一个 ticksInterval 变量保存 setInterval 的引用，并定义了两个处理函数：startTicks 用于启动定时器，stopTicks 用于停止定时器。主线程通过消息控制这些操作。

**代码逐行解析**
**1. 变量声明**
let ticksInterval

- **ticksInterval**：使用 let 声明的变量，用于存储 setInterval 返回的定时器 ID。初始值为 undefined，在调用 setInterval 时会被赋值，用于后续停止定时器。

**2. 消息事件监听**
self.addEventListener('message', function(ev) \{ ... \}, false);

- **self**：指向 Web Worker 的全局作用域（相当于主线程中的 window）。
- **addEventListener('message', ...)**：监听主线程通过 postMessage 发送的消息。
- **ev**：事件对象，包含消息数据，可通过 ev.data 访问。
- **false**：表示事件监听器在冒泡阶段触发（默认设置，适用于大多数场景）。

**3. 处理函数对象**
const handlers = \{ startTicks: (data) =\> \{ ticksInterval = setInterval(() =\> \{ self.postMessage(\{ type: 'tick' \}) \}, data.delay) \},
stopTicks: () =\> \{ clearInterval(ticksInterval) \}\}

- **handlers**：一个对象，映射消息类型到对应的处理函数。
    - **startTicks**：启动定时器的函数。
        - **参数**：data（消息的负载，预期包含 delay 属性，表示定时器间隔时间，单位为毫秒）。
        - **功能**：使用 setInterval 创建一个定时器，每隔 data.delay 毫秒向主线程发送 \{ type: 'tick' \} 消息。
        - **赋值**：将 setInterval 返回的 ID 存储在 ticksInterval 中，以便后续停止定时器。
    - **stopTicks**：停止定时器的函数。
        - **功能**：调用 clearInterval(ticksInterval) 清除由 ticksInterval 引用的定时器。

**4. 消息处理逻辑**
if (handlers[ev.data.type]) \{ handlers[ev.data.type](ev.data)\}

- **条件**：检查消息的 type 属性（ev.data.type）是否在 handlers 对象中存在。
- **操作**：如果存在匹配的处理函数，则调用该函数，并将整个 ev.data 对象作为参数传递。

**工作原理**

1. **初始化**：
    - Worker 启动时，声明 ticksInterval 为 undefined。
    - 设置 message 事件监听器，准备处理主线程发送的消息。
2. **消息处理**：
    - 主线程通过 postMessage 发送消息，Worker 接收后解析 ev.data。
    - 消息预期是一个对象，包含 type 属性，例如 \{ type: 'startTicks', delay: 1000 \} 或 \{ type: 'stopTicks' \}。
3. **启动定时器**：
    - 如果消息的 type 为 'startTicks'，则调用 startTicks 处理函数。
    - startTicks 使用 setInterval 创建定时器，每隔 data.delay 毫秒发送 \{ type: 'tick' \} 消息。
    - 定时器 ID 存储在 ticksInterval 中。
4. **停止定时器**：
    - 如果消息的 type 为 'stopTicks'，则调用 stopTicks 处理函数。
    - stopTicks 使用 clearInterval(ticksInterval) 停止定时器。
5. **通信**：
    - Worker 使用 self.postMessage 向主线程发送消息（例如 \{ type: 'tick' \}）。
    - 主线程可以通过监听 message 事件接收这些消息。

**使用示例**
以下是主线程如何与该 Worker 交互的示例代码：
_// 创建 Web Worker_const worker = new Worker('worker.js'); _// 假设代码在 worker.js 文件中_
_// 监听 Worker 发送的消息_worker.onmessage = function(event) \{ if (event.data.type === 'tick') \{ console.log('收到 tick，时间：', new Date().toISOString()); \}\};
_// 启动定时器，间隔 1 秒_worker.postMessage(\{ type: 'startTicks', delay: 1000 \});
_// 5 秒后停止定时器_setTimeout(() =\> \{ worker.postMessage(\{ type: 'stopTicks' \});\}, 5000);
**运行效果**

- Worker 每隔 1 秒向主线程发送 \{ type: 'tick' \} 消息。
- 主线程收到消息后打印时间戳。
- 5 秒后，主线程发送 stopTicks 消息，Worker 停止定时器。

**主要特性**

1. **模块化**：通过 handlers 对象组织处理函数，便于扩展新的消息类型。
2. **非阻塞**：在 Web Worker 中运行定时器，不影响主线程的 UI 响应。
3. **简单通信**：通过 postMessage 实现主线程与 Worker 的双向通信。
4. **动态配置**：定时器间隔（delay）由主线程消息动态指定。

**可能的改进**

1. **错误处理**：
    - 验证 data.delay 是否为正数。
    - 处理重复调用 startTicks 的情况（例如，清除现有定时器）。
    - 示例： startTicks: (data) =\> \{ if (typeof data.delay !== 'number' || data.delay \<= 0) \{ self.postMessage(\{ type: 'error', message: '无效的 delay 值' \}); return; \} if (ticksInterval) clearInterval(ticksInterval); _// 清除已有定时器_ ticksInterval = setInterval(() =\> \{ self.postMessage(\{ type: 'tick' \}) \}, data.delay);\}
2. **扩展消息类型**：
    - 添加 pauseTicks 或 resumeTicks 处理函数，实现暂停和恢复功能。
    - 添加 getStatus 处理函数，返回定时器状态。
3. **初始化检查**：
    - 在 Worker 启动或终止时确保 ticksInterval 被清除。
4. **调试支持**：
    - 添加确认消息，例如发送 \{ type: 'started' \} 或 \{ type: 'stopped' \}。

**应用场景**

- **实时更新**：定期更新 UI 元素，例如时钟或计数器。
- **轮询**：周期性检查新数据，例如轮询 API。
- **动画**：驱动动画或游戏循环，确保时间一致。
- **后台任务**：执行重复性后台任务，例如监控或日志记录。

**局限性**

1. **单一定时器**：ticksInterval 只能保存一个定时器，重复调用 startTicks 会覆盖之前的定时器。
2. **无持久性**：Worker 终止后，定时器状态会丢失。
3. **消息验证不足**：未检查无效的 type 或缺少 delay 属性。
4. **全局变量**：ticksInterval 是全局变量，在复杂 Worker 中可能引发问题。

**总结**
这段 Web Worker 脚本提供了一种简单高效的方式，用于管理一个周期性定时器，向主线程发送“tick”消息。它非常适合需要固定间隔且不阻塞 UI 的任务。通过 handlers 模式，代码结构清晰且易于扩展。稍加改进（例如错误处理、更多消息类型），即可适配更复杂的需求。
