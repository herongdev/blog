# 核心踩坑清单

> 本节目标：理解“核心踩坑清单”的核心思路，并能把它用于实际开发或面试表达。
|   |   |   |
|---|---|---|
|**序号**|**坑点**|**说明**|
|1️⃣|**依赖 node-only 模块**|比如：store、process、global、Buffer 等，Vite 编译时打包进 worker 后会出错。|
|2️⃣|**模块打包不兼容**|worker 里 import 的模块如果使用了 CommonJS，容易导致 Vite 打包失败或语法错误。|
|3️⃣|**路径问题**|worker 文件路径需要 Vite 正确处理，推荐用 new URL('./worker.ts', import.meta.url)。|
|4️⃣|**静态 import 陷阱**|worker 里用普通的 import 可能导致整个依赖链被过度打包，建议使用动态 import（import()）|
|5️⃣|**无法共享主线程上下文**|worker 里没有 window、document、localStorage、Vue 组件实例、Pinia、Vuex。只能通过 postMessage 传递数据。|
|6️⃣|**TypeScript 类型支持不完善**|Worker 全局对象（self）和事件类型容易写错，推荐手动声明类型，或者使用 vite-plugin-web-worker 辅助。|
|7️⃣|**跨域引用问题**|有些情况下 worker 文件被当作模块请求，服务端没配置好 CORS 导致无法加载。尤其是在生产部署时。|
|8️⃣|**大数据通信阻塞 UI**|传输大对象时容易卡死 UI，推荐使用 structuredClone() 或 Transferable Objects。|
|9️⃣|**Vite 构建模式不同**|开发模式和生产打包路径、URL、import 语法有差异。|
|🔟|**不能访问全局 polyfill**|比如：window.fetch() 是可用的，但如果用了某些库提供的 polyfill，在 worker 里未必能复用。|
|1️⃣1️⃣|**worker 关闭和内存泄漏**|创建了大量 worker 没有主动关闭 (worker.terminate()) 容易内存泄漏。|
|1️⃣2️⃣|**Source Map 调试不友好**|Vite 打包后的 worker 脚本调试不如主线程直观，尤其是在异常栈追踪时。|

**✅** **额外的框架相关坑（你目前这种 Vite + Vue 项目）**

|   |   |   |
|---|---|---|
|**序号**|**坑点**|**说明**|
|1️⃣|Vue Composition API 不可用|worker 里无法用 ref(), reactive(), computed() 等。|
|2️⃣|Pinia / Vuex 状态管理不可用|worker 是线程隔离，不能共享任何状态管理库。|
|3️⃣|import alias 需要 vite.config.ts 配置好 resolve.alias|否则 worker 里用 @/utils 这种路径会编译失败。|
|4️⃣|Vite 没内置 worker loader|需要手动用 new Worker(new URL('./worker.ts', import.meta.url), \{ type: 'module' \})。|

**✅** **稳定最佳实践模板**
我给你总结一份【以后你可以直接套用的 Vite + Vue + TypeScript 下的 Web Worker 模板】：

ts
复制编辑
// main.ts 里创建 workerconst worker = new Worker(new URL('@/workers/myWorker.ts', import.meta.url), \{ type: 'module' \})
worker.postMessage(\{ type: 'processOrders', data: myData \})
worker.onmessage = (event) =\> \{ console.log('收到worker消息', event.data)\}

ts
复制编辑
// workers/myWorker.tsself.addEventListener('message', async (event: MessageEvent\<MyWorkerMessage\>) =\> \{ const \{ type, data \} = event.data if (type === 'processOrders') \{ // 动态导入，避免静态依赖打包问题 const \{ heavyCompute \} = await import('@/utils/heavyCompute') const result = heavyCompute(data) self.postMessage(\{ type: 'processedOrders', data: result \}) \}\})

ts
复制编辑
// vite.config.ts (建议 alias 配置好)resolve: \{ alias: \{ '@': path.resolve(__dirname, './src') \}\}
✅ 这套写法能最大程度避免绝大多数坑。

**✅** **工具推荐**

|---|---|
|**工具**|**用途**|
|vite-plugin-web-worker|自动帮你处理 worker 路径、打包、类型声明|
|vite-plugin-worker-loader|兼容 webpack-style worker 引用|

**✅** **最后一条建议**
**Worker 本质上就是 "沙箱"。**
里面逻辑保持纯净、纯数据处理，效果会非常稳定。
你可以把 Worker 当成一个前端的 "后端服务" 去设计，越纯越好。
