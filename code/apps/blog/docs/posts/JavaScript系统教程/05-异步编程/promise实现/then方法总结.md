# then方法总结

> 本节目标：理解“then方法总结”的核心思路，并能把它用于实际开发或面试表达。
创建一个新的`P`，然后返回它；
然后在`P`的构造函数中，我们执行以下逻辑；

- 实现透传
- 当`P`的状态凝固时，我们立即调用成功回调和失败回调；
- 当`P`的状态为`pending`时，我们将成功回调和失败回调放入回调函数数组中。

我们调用以及放入回调数组的成功和失败回调是经过包装过的，它做了以下处理：

- 对回调函数调用的代码进行`Try catch`包装，以对回调函数执行时内部抛出的错误进行捕捉；比如`finally`的实现中，`Promise.resolve(fn())`，`fn()`内部抛出了一个错误；
- 对成功回调函数和失败回调函数的返回值进行判断，是否是一个`promise`对象；
    - 如果是`promise`对象，则添加回调，并将状态值传递出来；
    - 如果不是，就直接`resolve`这个回调函数的返回值；

then回调函数的执行逻辑
执行成功回调时：

- 先看这个回调执行会不会报错，如果会报错，`then`所创建期约会`reject`，后续`then`的失败回调会执行；
- 如果没有报错，我们取回调函数的执行结果，然后进行判断：
    - 如果不是期约，直接`resolve`这个执行结果；
    - 如果是期约，我们给这个期约添加回调函数，并且等待它的状态凝固；
        - 如果这个期约状态凝固为成功，`then`所创建的期约会`resolve`这个期约的成功值，，后续`then`的成功回调会执行；
        - 如果这个期约状态凝固为失败，`then`所创建的期约会`reject`这个期约的失败原因，，后续`then`的失败回调会执行；

执行失败回调时：

- 如果没有定义失败回调，默认的失败回调为：`err` `=\>` `{` `throw` `err` `}`，即抛出错误；
- 先看这个回调执行会不会报错，如果会报错，`then`所创建期约会`reject`，后续`then`的失败回调会执行；
- 如果没有报错，我们取回调函数的执行结果，然后进行判断：
    - 如果不是期约，直接`resolve`这个执行结果；
    - 如果是期约，我们给这个期约添加回调函数，并且等待它的状态凝固；
        - 如果这个期约状态凝固为成功，`then`所创建的期约会`resolve`这个期约的成功值，，后续`then`的成功回调会执行；
        - 如果这个期约状态凝固为失败，`then`所创建的期约会`reject`这个期约的失败原因，，后续`then`的失败回调会执行；

简言之，`then`在执行回调函数时，会检查回调函数的返回值，如果是期约，则等待它的状态凝固；并且在它所等待的期约状态成功时，将自身创建并要返回的期约状态改为成功，`relove`它所等待的期约的成功值；在它所等待的期约状态失败时，将自身创建并要返回的期约状态改为失败，`reject`它所等待的期约的失败原因；

由此可知，`finally,catch`等后面通过`then`添加的回调函数，都要`finally`和`catch`中定义的`promise`状态凝固才会执行；

- 不管如何，要`then()`后面的`then`中的回调执行；我们要先将当前`then`的成功或失败回调执行完才行；有可能是立即执行的回调（订阅了一个状态立即凝固的`promise`），也有可能是异步执行的回调（订阅了一个状态为`pending`的`promise`）；
