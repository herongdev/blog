# 持久化的响应式状态

> 本节目标：理解“持久化的响应式状态”的核心思路，并能把它用于实际开发或面试表达。
一、使用 import \{ useStorage \} from '@vueuse/core'
二、使用userStorage创建一个响应式的ref
三、序列化可以使用
structuredClone和JSON.stringify

坑：有的数据，比如vue的响应式对象，序列化时可能报错，这时，可以使用toRaw处理一下；

**Vue3 响应式对象 = Proxy**

- 你在模板里拿到的 tab 其实是 **Proxy**，带有内部的 [[Handler]]、[[Target]] 等槽位。
- 这种对象对浏览器原生的深拷贝 / 序列化工具来说并不是“普通可克隆数据”，
    - structuredClone(tab) 直接抛 DataCloneError；
    - JSON.stringify(tab) 在某些情况下会成功，但若遇到循环引用或不可枚举属性也可能失败。

**2. useStorage 的序列化流程**

1. **默认**：value =\> JSON.stringify(value)
2. 你自定义了序列化器，里面先 toRaw ➜ 得到 **纯粹的 \{ id: 1, symbol: '3M', ... \}**
3. 再 JSON.stringify() ➜ 100% 成功，写入的是合法 JSON 字符串
4. 读出来时 JSON.parse() ➜ 拿到正常对象，Vue 再次包装成响应式，功能不受任何影响

**3. 为什么不用 structuredClone**

- 早先你尝试过JSON.stringify(structuredClone(v))结果碰到了 **DataCloneError**，正是因为 v 还是 Proxy。
- 如果先 toRaw(v)，其实已经变回“干净对象”，JSON.stringify 足够，也就**不再需要** structuredClone 这一步了（反而多此一举）。
