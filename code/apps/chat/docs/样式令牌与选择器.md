# 样式令牌与选择器

为统一下拉菜单的位置和字体，项目采用可控的公共选择器。输入框的统一模型入口使用公共 Select，按数据来源分组；本地场景使用菜单底部的原生单选控件，回放速度使用原生 range 滑块；全站继续使用 CSS Modules，并集中管理设计令牌。

## 为什么原来的菜单样式不受控

原生 `<select>` 的关闭态属于页面控件，展开后的传统选择器由浏览器或操作系统绘制；修改页面的字体、padding 或 z-index 无法保证系统菜单同步变化。截图中的精确偏移还会受到系统和浏览器环境影响，不能仅凭截图断定某一个 CSS 偏移量错误。[MDN：自定义 select](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select)

本项目改为在页面中渲染按钮和 listbox，通过已有的 Floating UI 定位。弹层与触发按钮使用同一字号、字体和字重令牌，Portal 不依赖某个业务容器的字体继承。

## 职责分工

| 入口                                      | 职责                                                                                     |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| `src/styles/tokens.css`                   | 全站设计值的唯一入口：颜色角色、字阶、间距、圆角、阴影、动画、层级、图标、布局和代码高亮 |
| `src/styles/global.css`                   | 基础继承、表单重置、焦点、文字选择及减少动画设置                                         |
| `src/styles/primitives.module.css`        | 品牌标记、通用图标按钮等小型视觉复用                                                     |
| `src/styles/overlayGeometry.ts`           | 将两个以 px 定义的浮层间距令牌交给定位引擎，每次定位重新读取                             |
| `src/components/Select/useSelect.ts`      | 开关状态、定位、列表导航、文字定位、选择和禁用处理                                       |
| `src/components/Select/Select.tsx`        | 泛型 props、combobox/listbox/option 结构、Portal 和焦点管理                              |
| `src/components/Select/Select.module.css` | 触发器变体、菜单尺寸、选中态、字体、换行与滚动                                           |
| `src/components/Icon/`                    | 用 xs / sm / md / lg / hero 档位统一图标尺寸及笔画                                       |
| 各业务的 `*.module.css`                   | 使用令牌描述本组件的布局、状态及响应式变化                                               |

公共 `components` 不导入 app 或 feature；业务通过 props 传选项和回调。导入边界由 ESLint 与反例测试检查，避免公共控件混入聊天状态或模型 API。

## 如何改外观

常用调整入口：

| 需求                         | 令牌                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| 全站字体                     | `--font-sans`，代码用 `--font-mono`                                  |
| 所有选择器的触发器和弹层字号 | `--text-control`                                                     |
| Markdown 正文字号            | `--text-body-size`；手机正文使用 `--text-md`                         |
| 品牌色和交互背景             | `--accent`、`--accent-deep`、`--accent-soft`                         |
| 主要/次要/辅助文字           | `--text-primary`、`--text-secondary`、`--muted`                      |
| 常规边框和焦点               | `--border`、`--border-focus`、`--focus-ring`                         |
| 内容宽度及左右留白           | `--layout-content`、`--layout-gutter*`                               |
| 输入区高度边界               | `--layout-textarea-min-height`、`--layout-textarea-max-height`       |
| 菜单间距、避让和高度上限     | `--overlay-gap`、`--overlay-viewport-padding`、`--select-max-height` |

尺寸/字号主要使用 rem，浏览器默认根字号没有被锁成固定 px。间距刻度的数字表示根字号为 16px 时的名义像素值，如 `--space-12: 0.75rem`。原来分散的近似颜色、奇数字号和间距已归入共同尺度。需要改某一种交互时修改语义令牌；需要统一密度时修改尺度。不要为了保留每个历史像素而新增同义变量。

代码高亮不再全局导入第三方主题 CSS。Markdown 模块用 `:global(.hljs-...)` 在自身容器中匹配插件语义类，颜色引用 `--syntax-*`。

## 允许保留的字面值

- `0`、`auto`、`100%`、`1fr`、`100dvh`、居中位移、旋转角度和列表列数属于结构表达，不创建无意义令牌。
- CSS 媒体查询不能直接读取 `var()`。本项目保留 760px（手机）、1100px（紧凑桌面）、1450px（宽屏）三个约定值，样式守卫拒绝未登记的宽度断点；调整断点需同步组件查询和该检查。
- Floating UI 的 x/y、实际可用宽高、触发器实测宽度和 textarea 的 scrollHeight 是运行时测量结果，可以写入内联样式。`--select-anchor-width` / `--select-available-width` / `--select-available-height` 是实例测量值，不是设计令牌。
- 边框厚度、阴影和定位引擎读取的两个间距令牌可以在令牌文件内使用 px。组件不能再复制这些值。

`tests/architecture/styles.test.mjs` 随 `npm run check` 检查 CSS 声明中的硬编码颜色/绝对尺寸/字体/层级，变量未定义与循环依赖，以及 TSX 的静态图标尺寸和内联样式。它是本项目约定的轻量静态守卫，不替代浏览器的布局和可访问性测试。

## 菜单行为

- `autoUpdate` 在滚动、窗口变化、锚点和弹层尺寸变化时重新定位；卸载时由库清理监听器。
- `offset`、`flip`、`shift`、`size` 组合处理间距、向上展开、贴边避让和可用尺寸。宽度至少容纳触发器，受可用视口限制；长标签换行，长列表滚动。
- `useListNavigation`、`useTypeahead` 负责方向键、Home/End 和按文本定位；`useDismiss` 与 `FloatingFocusManager` 处理关闭和焦点返回，使用非模态菜单。
- 激活选项后才提交值；Escape 取消当前导航，不改选择。禁用时无法打开，生成结束后恢复。
- 所有菜单按钮显式 `type="button"`；选项点击取消表单默认行为，避免通过 Portal 的事件冒泡误发送输入草稿。

实现依据：[Floating UI 列表导航](https://floating-ui.com/docs/uselistnavigation)、[文字定位](https://floating-ui.com/docs/usetypeahead)、[尺寸约束](https://floating-ui.com/docs/size)。这些通用行为复用现有依赖，业务样式和选项数据由项目自己维护。

## Tailwind CSS 的选择

当前决定：保留 CSS Modules + CSS 变量，不新增 Tailwind 依赖。

Tailwind 支持设计令牌，其 `@theme` 可以同时生成工具类和 CSS 变量；它适合以工具类作为统一样式接口的团队。[Tailwind：Theme variables](https://tailwindcss.com/docs/theme)

本项目已经有清晰的 CSS Modules 边界，需求是统一设计值和修复控件交互。迁移 Tailwind 会同时改变 TSX 写法、样式构建和团队约定，对这次原生弹层问题没有直接帮助。继续使用现有方案能让逻辑、结构、样式职责保持明确。

以后如果团队统一采用 Tailwind，可将现有语义变量映射到 `@theme inline`，逐个组件迁移，并约束任意值写法；不要另建一套重复调色板。与 CSS Modules 混用时应遵循官方 `@reference` / CSS 变量方案，避免在每个模块重复处理整个框架。[Tailwind：兼容性与 CSS Modules](https://tailwindcss.com/docs/compatibility)

## 验证

`tests/e2e/select.spec.ts`，通过真实菜单操作检查上下定位、动态字体令牌、键盘导航、Esc/Tab、草稿隔离、禁用恢复、320px/390px 视口、窗口尺寸变化、超长模型名和长列表。原有 E2E 的选项操作改为真实点击 combobox 和 option，不保留隐藏原生 select 来绕过测试。

验证命令：

```sh
npm run check
PLAYWRIGHT_CHANNEL=chrome E2E_PORT=4187 npm run test:e2e
```

完整运行结果与环境见 [最新验收记录](试岗交付说明.md#四实际验收记录)。

测试使用 Chrome 和隔离服务，不调用真实模型 API。屏幕阅读器、Safari、Firefox、系统显示缩放及手机软键盘仍需对应环境实测；改变 CSS 字号令牌和视口尺寸不能替代这些验证。
