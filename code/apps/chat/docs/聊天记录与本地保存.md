# 聊天记录与本地保存

聊天记录现在自动保存到当前浏览器的 IndexedDB。刷新、重新打开相同地址或更新前端代码后，可以恢复已有会话、当前会话、模型、原始消息、思考过程、来源引用、输入草稿和已读取的文本和图片附件草稿。保存过程默认静默，仅失败或冲突时在输入区下方提示。每条会话的“更多操作 → 导出记录”可下载该会话的 JSON，包括消息、草稿、附件和所属项目元数据；不会包含其他会话。

浏览器按来源隔离存储：协议、主机、端口必须一致。开发地址 `http://127.0.0.1:5173` 和生产地址 `http://127.0.0.1:3001` 的历史不共用；`localhost` 和 `127.0.0.1` 也不同。没有账号和跨设备同步。清理网站数据、无痕窗口结束或浏览器回收存储可能删除记录，重要会话可通过其“更多操作 → 导出记录”备份为 JSON。旧版本已经丢失且未保存的会话无法追溯恢复。

## 会话管理

第一条提问会自动作为会话标题：合并空白后截取前 28 个 Unicode 字符，不额外调用模型。手动重命名后保留自定义标题，包括先为新会话命名再发送消息的情况。

每条会话右侧的“…”按钮提供重命名、置顶/取消置顶、归档/取消归档和删除。置顶会话优先展示；从侧栏左下角“用户设置 → 已归档”可查看和恢复归档会话，归档列表顶部提供“返回聊天”。删除必须在确认窗口中确认，取消和 Esc 均不删除。菜单支持键盘导航和移动端，不接管原生右键菜单。

管理状态与消息一并持久化，兼容没有这些字段的旧记录。归档或删除正在生成的会话会先停止请求，当前页面切到其他未归档会话；没有可用会话时创建空白会话。操作其他会话不会中断当前生成。

删除成功后清除该记录的标题、消息、草稿和附件，仅保留用于同步冲突检测的最小删除标记与标识字段，导出不包含已删除记录。旧标签页的后续写入会被拒绝，刷新恢复日志也不能恢复已删除会话。仍需等待本地保存成功；存储错误沿用现有重试反馈。

| 对象仓库        | 用途                                                                   |
| --------------- | ---------------------------------------------------------------------- |
| `conversations` | 会话清单、草稿、附件引用、消息数量、修订 ID 与修改时间；不内嵌历史消息 |
| `messages`      | 按会话 ID 和消息 ID 保存正文、活动和来源，以位置索引恢复顺序           |
| `assets`        | 独立的图片 Blob，按会话建立清理索引                                    |
| `summaries`     | 标题、模型、消息数量、草稿标记、置顶、归档和项目归属，不携带正文或附件 |
| `search`        | 标题、草稿、每条消息分别建立规范化文本记录                             |
| `meta`          | 最近选择的会话、独立项目记录和迁移异常标记                             |

启动按排序索引读取首页 50 条摘要，再按 ID 读取当前会话的消息。普通、归档和项目目录分别保留分页游标，通过“加载更多”继续读取，加载失败可重试。当前会话即使不在首页也单独恢复。切换会话时按需读取，读取期间保留原页面，目标准备好后再切换。加载失败显示重试和取消入口。非当前且已结束的会话按导航释放正文引用；仍在生成的后台会话保留正文，确保增量事件可继续归并。尚未提交的写入保留完整快照。后台会话的重命名、归档、移动和导出先补齐正文，避免用空的摘要覆盖原始记录。单标签页另用 sessionStorage 保存自己的当前会话选择和未提交恢复日志。

草稿及附件属于需要恢复的会话数据，通过 props 交给 Composer。输入框尺寸、文件读取状态、引用页码、活动展开状态仍由相应组件或 Hook 管理。正文不会因为主题、语言或 Markdown 展示补全而被改写。API 密钥仍由服务端读取，历史保存逻辑不接触服务端配置。

## 保存与恢复规则

- 初始化先完成读取，再开放聊天输入，避免空的初始页面覆盖已有数据。
- 对发生变化的会话，只写变化的消息、草稿或标题索引；已提交的历史消息和图片不会随每次草稿编辑重写。使用 200ms 固定间隔合并写入；连续流式输入不会把保存无限推迟到结束。只有事务提交成功才显示“已保存”。
- 进入后台或触发 `pagehide` 时先提交 32ms 流式缓冲，再同步记录变化的消息、最后两条消息和消息 ID 顺序到当前标签页的恢复日志；新建且未入库的会话保留完整日志，已入库图片只保留引用。普通刷新会合并恢复日志与数据库；不能保证浏览器崩溃、强制退出或断电时最后一个尚未落盘片段不丢失。
- 恢复时将 `waiting` / `streaming` 回答改成中断终态，保留已经收到的正文和活动，允许用户重新生成；不自动调用模型。已完成、错误、主动停止等终态保持原意。
- 迁移时校验每条原始记录，启动时校验摘要并检查正文/摘要数量，按需读取时校验正文。损坏或不支持版本的记录保留原样，可用记录照常恢复；正文错误最迟在打开该会话时报告，不为了启动校验加载所有正文。
- 同一会话写入前，在同一事务内检查修订 ID。不同标签页的新会话不会相互清空；同一会话发生冲突时拒绝覆盖并保留页面内容。刷新时，冲突的恢复日志会保留为另一条会话，避免覆盖另一标签页的结果；已删除会话的旧恢复日志会丢弃，防止恢复已删内容。
- 存储被禁止、写入失败或空间不足时继续保留内存内容，显示失败提示，支持重试及导出；不会静默删除最旧会话腾空间。

## 项目与会话归属

侧栏“项目 → 新建项目”输入名称后，进入项目的首个空白对话。项目名称去除首尾空白，长度上限与输入框一致为 80 个 UTF-16 代码单元；允许同名项目，归属通过独立 ID 区分。

- 项目名右侧的新建图标在指定项目中创建对话并继承当前模型；顶部“新聊天”创建普通对话。
- 会话的“更多操作 → 移至项目”可以迁移到已有项目；选择“不属于任何项目”可移出。移动保留消息、草稿、附件、模型、置顶与归档状态，不中断正在生成的回答。
- 项目记录写入现有 IndexedDB 的 `meta`，以 `project:<id>` 为独立键。创建项目与首个会话在同一个事务中提交，项目也进入刷新恢复日志；导出会话时附带其所属项目元数据。不同标签页创建的项目分别保存，刷新后可看到彼此的新项目。
- 会话增加可选 `projectId`，旧记录仍可直接读取。项目记录损坏时会报告读取问题，其会话回到普通列表显示，避免成为无法访问的记录。
- 本版项目用于组织会话，不共享模型上下文、文件或指令，也不提供云端协作。项目名称不会作为提示词发送给模型。

交互参考 [ChatGPT Projects 官方说明](https://learn.chatgpt.com/docs/projects)，使用本项目现有的组件、令牌和本地保存机制实现，没有引入额外依赖。

项目回归命令：`npm run test:e2e -- tests/e2e/projects.spec.ts`。覆盖创建与草稿恢复、项目内新建、流式生成中迁移与移出、并发创建、手机深色弹窗、键盘取消和长名称布局；纯状态与数据兼容性见 `src/features/chat/state/projects.test.ts`。

### 项目菜单

项目行右侧的“…”提供重命名项目、置顶／取消置顶、删除项目，旁边的编辑图标可在该项目中新建对话。点击项目名称独立展开或收起该项目，允许多个项目同时展开；展开不会切换当前聊天、清空草稿或打断生成。点击会话条目才进入聊天，右侧图标新建会话时展开对应项目。展开状态在侧栏开关、归档视图切换和虚拟列表卸载时保留；刷新后默认展开当前聊天所属项目。各项目独立按需加载和分页。

删除前显示确认框，默认焦点在“取消”。删除项目保留其中所有会话的内容、草稿、附件和归档状态，将其移回普通对话记录；正在生成的回答继续接收。项目留下不含名称的删除标记，阻止旧标签页恢复。重命名、置顶和删除由独立版本号检查，项目更新与已加载的相关会话更新在同一事务提交；未加载会话通过项目删除标记在读取时解除归属，后续编辑再写回正文。刷新日志也记录项目的基础版本，恢复时不覆盖其他标签页保存的新版本；发生冲突会提示。

菜单共用 `ActionMenu`，负责 Floating UI 定位、键盘方向键、Escape、外部点击和焦点恢复。项目业务操作在 `useChat`／reducer，展示组件只接收数据和回调。未提供分享和项目设置入口，避免在尚未支持共享权限或项目上下文配置时出现空操作。

回归：`npm run test:e2e -- tests/e2e/project-actions.spec.ts tests/e2e/projects.spec.ts tests/e2e/conversation-actions.spec.ts tests/e2e/history.spec.ts`。

## 本地搜索

侧栏顶部的放大镜打开搜索，也支持 `⌘ / Ctrl + K`；其他对话框打开时不抢占快捷键。标题、用户与助手消息正文、未发送文字草稿均可匹配，包含项目内和已归档会话，排除已删除记录。关键词按字面连续片段搜索，忽略英文大小写并统一空白字符；不执行用户输入的正则表达式，不读取图片内容、来源全文或独立思考过程。

空关键词显示最近会话；标题命中优先，结果提供正文摘要、关键词高亮、项目名和归档标记。每页显示 50 条并标出总数，支持上一页、下一页，也可以继续输入缩小范围。点击或按 Enter 打开会话；方向键移动结果焦点，Escape 关闭。打开或关闭搜索不影响生成与草稿，切换到另一条会话也不会停止生成；各聊天的正文、错误和停止操作独立。当前版本打开对应会话，不自动定位到命中消息。

搜索在 Web Worker 中查询独立的本地文本表，不调用搜索 API。正文、摘要和文本记录在同一事务中保存；尚未提交的变化作为查询覆盖项合并。关键词查询每批扫描 256 条文本，完整字面匹配后按会话去重；命中较少时按 ID 读取摘要，较多时分批关联摘要。空查询走最近会话排序索引。关键词检索用有界堆保留当前页需要的排序前缀，命中 ID 集合仍随结果数量增长。Worker 只缓存最近一次查询的前 1000 条摘要和文本 ID，按查询、数据库修订号及待保存覆盖项失效；当前页才读取命中文本生成片段，缓存范围内翻页无需重扫，深页重新查询。结果只返回当前页的摘要，不把完整消息和附件传回页面。

输入有 120ms 防抖，查询支持取消与过期结果隔离。线程代码随主页面资源内嵌，首次打开搜索也无需额外请求脚本；页面已加载时断网仍可搜索已有记录，这不代表应用支持离线冷启动。其他标签页的更新仍需刷新页面后完整使用。

数据转换在 `lib/conversationSummary.ts`、`lib/textIndexRecords.ts` 和 `lib/searchConversations.ts`；结构升级在 `services/chatDatabase.ts`，批次整理在 `services/chatMigration.ts`；后台查询及生命周期在 `services/searchCandidates.ts`、`services/chatSearch.worker.ts`、`services/chatSearchClient.ts`；查询状态在 `hooks/useChatSearch.ts`；展示和样式在 `ChatSearchDialog.tsx` 及同名 CSS Module。

验证：`npm run test:e2e -- tests/e2e/search.spec.ts tests/e2e/sidebar.spec.ts`，覆盖刷新恢复后的离线搜索、项目和归档结果、当前生成保护、空状态、手机深色英文、键盘与焦点、草稿保留。字面特殊字符、中英文、长正文摘要及结果上限见 `lib/searchConversations.test.ts`。

## 大量记录的渲染

侧栏普通会话、项目列表、展开的项目会话使用公共 `WindowedList`。只挂载视口及其附近的条目，按实测行高定位；尺寸监听与滚动监听会在卸载时清理。行高估值从 CSS 令牌计算，密度和窗口变化后重新测量。方向键、Home 和 End 可移动到尚未挂载的条目，当前焦点行保留挂载。

80 条以内的对话使用自然文档流；更长的对话使用同一套可变高度虚拟列表，按视口范围双向挂载和卸载消息，滚动到顶部不会累积全部历史 DOM。测量高度变化时补偿阅读锚点，底部跟随继续交给 `useAutoScroll`；键盘菜单独立处理按键。窗口内消息以 ID 保持身份，卸载后的活动展开与表格页码通过会话内最多 200 项的缓存恢复，较久且被淘汰的状态恢复默认。缓存不复制正文。主动表格翻页变短时保持表格可见，按钮禁用造成焦点丢失时解除失效的行固定。发送、复制和导出仍使用原始数据。

Markdown 追加时复用稳定的语法块，重解析末尾两个块；文档含引用式链接定义时整篇解析，保持全局引用语义。超过 20000 字符的块跳过语法高亮；代码区限制可视高度但复制完整代码。表格每页最多挂载 50 行，保留表头和翻页按钮，原始 Markdown 不截断。语法解析仍有处理超长单块的成本。

### 图片与模型上下文

图片在数据库中独立保存为 Blob。消息仅引用附件 ID、尺寸与编码长度；缩略图和预览挂载时读取，Object URL 使用引用计数，最后一个使用者卸载后释放。导出和请求发送时才恢复所需图片的 data URL；删除会话和移除不再使用的附件会在事务内清理图片。导出失败提供重试入口，不生成缺少图片的备份。

模型请求由 `lib/contextBudget.ts` 从近期向前选择完整轮次，最多 80 条消息、96000 UTF-8 文本字节，并遵守共享图片预算及单条字段限制。超过预算只裁剪请求上下文，不删除历史；回答显示近期上下文提示。当前提问本身过大则提示缩短，不静默截断。此处是应用传输预算，不是厂商 tokenizer，也不承诺精确覆盖每个模型的上下文窗口。

侧栏通过 `ChatCatalog` 和 `useSyncExternalStore` 订阅标题、归属、置顶等元数据。流式正文更新不发布目录快照；高频状态更新定位当前会话，避免重新归约所有会话。


当前会话的全部消息仍一次读取至内存；已加载的目录页在会话期间保留。搜索首查需要遍历候选，短词可能涉及全库，精确总数的去重集合随命中会话数增长。首次升级需处理旧数据；大量导出需恢复完整图片，存在峰值内存成本。测量脚本覆盖一万条会话、两千条消息、两百张图片的固定样本，不代表十万条数据或所有设备和浏览器的容量认证。

新增风险回归：`tests/e2e/scale-optimizations.spec.ts` 验证长历史请求预算、大表格翻页与完整代码复制、图片分表及无关写入和删除清理。性能采样默认跳过，单独执行：

```bash
PERF_RUN=1 PERF_LABEL=current npm run test:e2e -- tests/e2e/performance-baseline.spec.ts --workers=1
```

输出为 `output/performance/current/`。时延是本机观测值，不设置跨设备时延门槛；`serializedChars` 统计写入对象的 JSON 字符数，不等同磁盘字节数，`blobBytes` 单独统计二进制负载。

## 打开历史的异步边界

打开尚未加载的会话时，保留当前页面，显示打开进度和取消入口。读取失败后显示独立错误及“重新读取”，不把失败误归到当前会话。新建对话、选择其他会话、返回当前会话、在项目中新建对话或主动取消，都会使旧的打开请求失效；迟到读取可补充缓存，但不能改变最新导航目标。

`useConversationNavigation` 管理导航请求身份和加载状态，持久化 Hook 负责数据读取，`ConversationOpenStatus` 只负责展示和回调。正式回归 `tests/e2e/history-navigation.spec.ts` 用延迟 IndexedDB 和读取失败验证抢占、取消、错误与重试，测试不调用真实模型。

## 多聊天后台生成

`useChat` 按会话 ID 保存独立 Run，每条任务有自己的 AbortController、消息 ID、事件缓冲和计时器；同一聊天只允许一个任务。新建普通聊天、创建项目、项目内新建、切换历史和搜索打开均不取消其他聊天。停止、归档或删除只终止目标聊天，停止前提交该任务缓冲，旧任务迟到数据和清理不能覆盖重发后的新任务。

存储层不释放仍在生成的后台正文；目录仅在生成状态改变时更新指示图标，不因逐字输出重复刷新。隐藏页面或保存检查点时提交全部任务缓冲。刷新、关闭页面和组件卸载结束网络连接，已收到内容保留，恢复后标记中断，不自动调用模型续跑。后台生成受浏览器运行状态、网络和服务端并发上限约束，不是关闭网页后仍执行的服务端任务。

[后台生成回归](../tests/e2e/background-generation.spec.ts)覆盖首包前并行、独立停止与重发、归档／删除后台任务、加载已释放历史时保护后台正文，以及多个聊天完成和刷新中断后的恢复；错误隔离沿用 `OSS-RUN-002`。
