# 图片附件与预览

## 使用方式

- 先选择支持图片的模型，再点输入框左侧「＋ → 添加图片」，或把本地图片、图表截图拖入整个聊天区域；在输入框中也可以粘贴剪贴板截图。
- 支持 PNG、JPEG、WebP。每次最多 3 个附件（图片和文本合计），每张图片不超过 4 MB；原图保留，不自动压缩图表文字。单边最多 8192 像素，总计最多 3200 万像素。
- 点击缩略图可预览、查看原始大小，Esc 或关闭按钮退出。发送后的消息也保留图片预览。
- 本地样例不接收新附件；文本模型的「添加图片」置灰，悬停、键盘聚焦或点击可查看切换视觉模型的提示，文本附件仍可使用。未发送过消息时切换来源或模型保留草稿与附件；已有消息时仍新建对话，避免跨模型混用历史。
- 文件拖拽只处理浏览器提供的 File，不抓取网页图片链接、HTML 或图表源码。网页图表可保存为图片或截图后添加。不接收 SVG、GIF、PDF、音视频。

## 模型与协议

默认模型列表增加百炼 `qwen3-vl-plus`、DeepSeek `deepseek-v4-flash-vision-exp`。若已通过环境变量显式指定 `DASHSCOPE_MODELS` 或 `DEEPSEEK_MODELS`，该列表仍优先，需要自行加入具有账户权限的视觉模型并重启后端。普通文字型号不会自动升级或静默丢弃图片。

前端和后端共用 `shared/contracts/images.ts` 中保守的视觉能力判断，目前确认支持 Qwen VL 系列和上述 DeepSeek 视觉型号。新型号上线时需核对官方接口再更新。视觉模型的可用性、地域和调用权限由实际账户决定。

请求中的用户消息通过独立 `images` 字段传递 data URL；服务端校验角色、格式、数量和大小后，转换为厂商 Chat Completions 的 `text` / `image_url` 内容块。只有用户消息允许图片，UI 文件名、预览尺寸和本地 ID 不会发送给厂商。纯图片提问、后续追问和重试均保留图片内容。完整历史中图片 data URL 总长度最多 16 MiB；客户端超过预算会保留草稿并提示减少图片或开启新对话。HTTP 请求体上限为 20 MiB。

官方依据：[百炼视觉接口](https://help.aliyun.com/en/model-studio/qwen-vl-compatible-with-openai)、[DeepSeek Vision](https://api-docs.deepseek.com/guides/vision/)。

## 职责和存储

- `useAttachments` 在读取前统一检查文件选择、拖拽和粘贴的模型能力，管理异步读取、错误反馈、删除和会话／模型切换隔离；`readAttachment` 检查文件签名并实际解码，释放 ImageBitmap。失败批次整体拒绝，保留原附件。
- `useFileDrop` 管理文件拖拽事件与默认导航阻止；App 只组合聊天区和浮层。
- `AttachmentList` 展示附件，`ImagePreview` 使用原生 dialog 管理模态焦点、Esc 与焦点返回。布局、明暗主题和尺寸使用 CSS Modules 与设计令牌。
- 图片草稿、已发送图片与聊天内容一起保存到 IndexedDB，旧文本历史无需清空或迁移。图片仅在发送时上传模型服务；本地预览不调用 API。
- 当前无账户与对象存储，采用有上限的内联图片。大图片不能保证塞进 sessionStorage 的页面退出应急日志，持久化以界面显示「聊天记录已保存在此浏览器」为准；保存失败应重试或导出。今后接入账户后，可将图片放对象存储，消息只引用附件 ID，减少每轮请求和保存时重复处理图片。

## 验证

`tests/e2e/attachment-capabilities.spec.ts` 验证前置禁用及 tooltip、三种输入路径共用能力校验、读取期间切换模型的迟到结果隔离。

`tests/e2e/images.spec.ts` 覆盖图片预览、关闭焦点、刷新恢复、图片单独发送、多轮上下文、拖拽、剪贴板截图、窄屏布局、类型伪装、大小和数量限制。`tests/integration/images.test.ts` 验证协议边界，`tests/integration/api.test.ts` 验证两家图片请求转换及文字模型拒收。全部使用模拟响应，不调用真实模型。
