## 验收范围

任务书第三节的 8 个模块均有实现与验证入口。按补充要求采用 React；验收主线使用附件 JSON，百炼与 DeepSeek 接入作为扩展能力。

功能行为有自动化验证；视觉流畅程度、效果图相似度和架构设计质量仍需人工评审。当前未建立截图像素基线或逐帧闪动指标。

## 原始材料一致性

- 任务书 SHA-256：`04d6ae64dd45772b378665b8a74adb9922e2df767ba94057d55c1ad2ecd95234`。
- 原始 `附件.json` 与仓库 `public/data/sample.json` 解析后的内容完全一致，均为 1,136 条事件。字节哈希不同是格式差异，不是业务数据变化。
- 附件包含 891 条正文事件、236 条思考事件；最终正文 891 字符，思考分两段，中间一次搜索工具调用；10 份 reference 资料，正文 16 组引用，其中 4 组包含两个来源。
- 文档的 `[id1,id2,...]` 是格式说明；附件实际 ID 为 `1_0` 等，并使用 `[[1_0][1_2]]`。测试覆盖 `[1_0,1_2]`、带空格逗号形式和附件嵌套形式，未宣称支持未定义的任意字符串 ID 协议。
- 测试从仓库读取附件，CI 不依赖个人文件目录；预期正文、思考和资料直接从原始事件提取，不通过待测 adapter 生成预期结果。

## 停止时草稿误提交的修复

复现步骤：发送问题 → 开始思考或工具调用 → 在输入框填写下一条草稿 → 点击“停止生成”。原实现虽然把旧回答标记为停止，却清空草稿并开始第二个请求，因此停止按钮看起来一直存在。

原因是 React 在生成状态切换时复用了同一个 button DOM 节点：点击处理更新状态后，该节点从 `type="button"` 变成 `type="submit"`，浏览器继续执行这次点击的默认动作，触发表单提交。以前停止测试没有保留非空草稿，表单的空输入保护掩盖了这个问题。

修复位于 [Composer.tsx](../src/features/chat/components/Composer.tsx)：停止点击先 `preventDefault()`，再调用原有停止逻辑。没有改写请求管理，也没有为此新增依赖。回归同时检查草稿不丢、停止后的请求不增加、按钮复位、工具标记已停止和用户之后仍可主动发送。

回归入口为 [assignment.spec.ts](../tests/e2e/assignment.spec.ts) 中的 `REQ-STATES`。

## 样例输入边界

`sampleEnvelope.ts` 在回放前验证 JSON 事件的外层结构、正文、来源和工具等已知字段；未知事件名称由适配器忽略，已知事件结构错误统一提示“本地样例格式不正确”。JSON 语法错误使用同样的受控提示，取消读取仍保留取消语义。

`sampleEnvelope.test.ts` 验证损坏结构、未知事件兼容和原附件适配结果不变；`tests/e2e/sample-validation.spec.ts` 验证错误反馈、按钮恢复、恢复有效文件后重新生成以及原有 16 处引用。
