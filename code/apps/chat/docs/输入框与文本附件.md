# 输入框与文本附件

输入框底栏左侧“＋”菜单分别提供「添加文本文件」「添加图片」和已支持模型的深度思考开关，开启思考后显示可关闭的状态标签。右侧是模型选择和发送按钮；生成中发送按钮切换为停止。模型切换遵循原有的新会话规则。本地样例的场景和回放速度选择收在统一模型菜单内，该模式的附件入口禁用，并提示先选择模型。

## 回放速率

本地样例的模型菜单使用分档滑杆选择 1×、1.5×、2×、3×、4×，五档等距排列，轨道显示已选择范围，标题同步显示标准、轻快、快速、高速或极速。可点击轨道或拖动滑块，也可使用方向键和 Home/End；Esc 关闭菜单后焦点回到模型入口。`ReplaySpeedSlider` 独立负责展示和数值回调，尺寸与配色沿用设计令牌，不改变原有回放逻辑。各档采用独立渐变并交叉淡入，滑块与填充同步过渡；加速时触发一次扫光，1× 以上显示随倍率加快的流动粒子。效果由 CSS 驱动，关闭菜单后卸载；系统开启减少动态效果时关闭粒子、扫光和过渡。

## 文本附件

- 支持 UTF-8 编码的 `.txt`、`.md`、`.json`，最多 3 个，每个不超过 16 KB。
- 选择文件后显示文件名，可逐个移除；附件内容只在点击发送时随提问交给当前模型。
- 文件在浏览器读取，按文件名和正文合并为聊天消息，不单独上传到文件存储。对话中的用户消息保留实际发送的文件内容。
- 附件可以单独发送；文本不支持空文件或二进制内容；图片处理见 [图片附件与预览](图片附件与预览.md)。不支持 PDF 或音频。
- 待发送附件按会话隔离，随会话草稿由存储模块管理；切换会话、模型或卸载时，尚未完成的读取结果会被丢弃；已读完的附件不因能力变化而丢失，发送前仍有校验。

文本模型保留文本附件入口，图片入口按视觉能力禁用。达到附件上限或读取中也会禁用入口并解释原因。禁用项通过 `aria-disabled` 阻止操作，同时保留键盘焦点和触摸提示；浮层由 Floating UI 定位，使用共享设计令牌。

## 实现与验证

App 通过 `modelControl` 插槽组合模型选择器与 Composer，两个业务模块保持独立。文件校验及消息拼接位于 `features/chat/lib/attachments.ts`，读取生命周期位于 `hooks/useAttachments.ts`，附件展示使用独立的 `AttachmentList` 及 CSS Module。控件使用共享设计令牌，模型名称超长时省略展示，完整选项在菜单中可读。

[输入框回归](../tests/e2e/composer.spec.ts) 验证附件增删、无效文件、消息内容、模型菜单不误提交、会话隔离和窄屏排列；[选择器回归](../tests/e2e/select.spec.ts) 验证菜单定位、键盘导航及长列表。[原题交互回归](../tests/e2e/chat.spec.ts) 继续验证发送、停止、模型切换和滚动。

```bash
npm run check
npm run test:e2e -- tests/e2e/composer.spec.ts tests/e2e/select.spec.ts tests/e2e/chat.spec.ts
```

测试使用本地模拟响应，不调用真实模型。完整验收基线与已验证环境见 [试岗交付说明](试岗交付说明.md#四实际验收记录)。
