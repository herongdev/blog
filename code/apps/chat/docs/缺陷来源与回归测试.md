## 复现条件与具体断言

### 输入法：OSS-IME-001

上游报告涉及 macOS Safari / Mac App 中组合输入时按回车误发送，同时还报告气泡预览导致的滚动变化。本项目没有气泡预览，本用例只迁移输入法确认键这一部分。

在输入框填入中文后，分别触发 `isComposing=true` 的 Enter，以及 `isComposing=false、keyCode=229` 的 Enter。检查没有创建消息、草稿未丢失。随后 Shift+Enter 应换行，普通 Enter 应创建且只创建一条用户消息并清空草稿。

浏览器测试模拟事件字段，不能替代真实 macOS 输入法候选窗或旧 Safari 的人工验证。Safari 的真实输入法行为尚待实测。

### 下划线和代码语言：OSS-MD-001 / 002 / 003

- #118 报告版本为 Streamdown 1.2.0。以 `hello_world` 等合法标识符和转义下划线作为输入，检查展示补全没有改写字面内容；额外保留真正未闭合斜体的正例，防止通过关闭全部补全让测试“变绿”。
- #137 报告版本为 1.2.0，后续讨论说明代码块重建时同一问题曾再次出现。使用两个未注册语言名，断言仍有代码容器、原始代码和后续段落。本项目渲染器使用 rehype-highlight，不依赖上游 Shiki 的内部接口。
- #433 报告版本为 Streamdown 2.3.0 / @streamdown/code 1.0.3。将含 rust 代码块的消息按每个字符前缀传入实际 MarkdownContent 渲染器；所有阶段不抛异常，最终中文代码和后续段落均可见。

这些断言调用实际渲染组件，不 mock 掉 Markdown 解析器或高亮器。

### 延迟加载失败：OSS-MD-004

上游报告版本为 Streamdown 1.6.10，场景是新部署删除旧哈希资源，而仍打开旧页面的用户后来才触发懒加载。本项目同样用 `React.lazy` 加载 Markdown，因此该失败条件适用。

测试拦截生产构建中真实的 `MarkdownContent-*.js` 请求并返回 404，然后从页面启动 Markdown 回答。断言拦截确实发生；回答显示原文、后续增量到达最终文字、输入框仍能发送第二条消息、第一条回答保持不变，且没有未捕获的页面异常。

修复前浏览器记录了 `Failed to fetch dynamically imported module`，回答区域消失。原来的 Suspense 只处理等待，没有接住拒绝的 import Promise。

修复增加 [MessageContentBoundary](../src/features/chat/components/MessageContentBoundary.tsx)，只包裹单条回答的 Markdown 区域。发生加载或渲染错误时显示当前原文，后续 props 更新继续呈现增量；发送、停止、复制、会话状态由原有模块负责。原文由 React 文本节点输出，不注入 HTML；样式独立放在同目录 CSS Module。

当前降级保持到该回答组件卸载。React.lazy 会缓存失败结果，后续消息也可能继续显示原文；恢复排版需要重新加载可用的页面资源。没有自动刷新，避免打断当前生成和阅读；已保存记录可在手动刷新后恢复。

复现步骤由 `OSS-MD-004` 浏览器用例执行，运行后可查看测试报告附件。

### 容器变矮：OSS-SCROLL-001

上游报告提到 use-stick-to-bottom 1.1.1 / 1.1.4 的内容观察无法覆盖 flex 相邻区域变高。本项目以真实输入框的多行草稿作为相邻区域，不通过修改内部 Hook 状态伪造条件。

生成完整回答后，记录阅读区的容器高度和内容高度。输入多行草稿时，断言容器确实变矮而内容高度不变，底部仍对齐。再离开底部阅读历史，重复增高输入区，等待尺寸观察与动画帧处理后，阅读位置仍不被拉回底部。

当前项目 useAutoScroll 已观察容器和内容尺寸，并按跟随状态决定是否回底部。

### 分片与协议解释：OSS-SSE-001 / 002、OSS-API-001

- #17 的关键是 CR 与 LF 可以由不同网络块送达。测试保留这个分块结构，覆盖 CR-only 与分离 CRLF 两种情况；多个 data 行最终只产生一个合并事件。
- #18 的报告希望 EOF 自动完成最后一帧，但维护者明确解释不能这样补全。已有测试继续要求缺少结束空行的事件不派发，也不把不完整 done 当成功。
- #8720 期待 Express 请求直接带有浏览器 AbortSignal。讨论解释 Express 使用 Node IncomingMessage，取消传播表现为连接终止。集成测试启动采用 Express 适配器的真实 Nest 路由并模拟上游，验证客户端取消后上游收到 abort。测试不声称能区分主动停止、关页和网络断开。
