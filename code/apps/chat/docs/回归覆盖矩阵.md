## 范围与编号

一个 issue 可以对应多个边界，多个 issue 也可能归并为同一个场景。用例数量不等于缺陷数量，当前覆盖不代表上游全部问题均已验证。完整运行结果统一见 [最新验收记录](试岗交付说明.md#四实际验收记录)。

编号含义：

- `REQ-*`：原任务书的功能与数据验收。
- `OSS-*`：有具体上游来源。表中区分直接同类场景与迁移风险，不代表依赖了整个上游 SDK。
- `APP-*`：审查中发现的本项目边界或从上游风险派生的组合场景。
- `LIMIT-*`：锁定已知约束，测试通过不表示实现了扩展功能。
- P0：内容丢失、串会话、页面不可用；P1：主要交互和显示错误；P2：兼容、体验及规模验证。

## 可执行场景：前置条件、步骤、断言

浏览器测试使用生产构建。可控流只替换浏览器 fetch 的 `/api/chat` 传输，页面的 useChat、reducer、协议解析、Markdown 和组件照常运行。模拟传输故意允许 abort 后送达一包，检查应用是否隔离旧 run。真实 Nest HTTP 取消和超时由已有集成测试负责；不把浏览器 fetch mock 当成真实断网证据。

## 本地发现与修复

| 问题                                           | 修复前证据                                            | 修复位置与边界                                                                        |
| ---------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 中文标点改变自动链接目标                       | 4 个标点用例失败；例如中文句号后的后文进入域名编码    | 新增纯 remark 插件，依据 AST 原始位置仅修正裸链接；明确链接和代码不动                 |

| P2 CJK 强调方言                  | 评估 remark-cjk-friendly 的语法、许可证与兼容性，再决定是否引入源码                | 当前保留 CommonMark，LIMIT 测试记录约束                   |
| 不适用：持久化/检索/多实例       | LibreChat 的上传文件孤儿、数据库429、Meilisearch并发等                             | 本项目没有对应后端数据能力                                |
| 不适用：恢复流/工具执行          | AI SDK 的 reconnect、重放持久化、工具审批或子代理等                                | 本项目停止即终止，不提供恢复流和真实工具执行              |
| 不适用：特定渲染功能             | 图片上传、数学公式、Mermaid、表格全屏/下载、流式动画插件等                         | 当前没有对应功能                                          |

新增功能或目标运行环境时，应补充相应的复现条件和验证。
