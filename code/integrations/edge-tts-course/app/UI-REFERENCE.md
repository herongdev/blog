# 本机文稿编辑器的布局依据

用户：在 Mac 上编辑旁白、理解停顿与画面，再生成当前视频，不操作 JSON 或时间轴。

实现前已实际查看 `docs/reference-clipchamp.png`。该截图来自 Microsoft Clipchamp 官方教程：
https://clipchamp.com/pt-br/blog/como-criar-narracoes-para-videos-de-demonstracao-do-produto/

参考的场景是文本转语音编辑：左侧组织内容，独立预览区，相邻的文本与声音属性，以及右上角唯一主要导出操作。当前工程按文字编辑优先：左侧场景、中间逐句台词与停顿、右侧当前画面或上次成片；保留原有暖白、陶土橙与 HR 小象。

页面没有增加声音选择、收费服务、账户或模型调用。停顿为每句最小间隔，不宣称可以剪掉原声自带停顿；“画面预览”不冒充已按新旁白生成的最终时间线。

## 视觉来源

`app/web/tokens.css` 是本机 WKWebView 与 Edge 界面的唯一样式 token 来源。默认跟随系统，也可显式选择浅色或深色；仅保存本机偏好。这里全部操作采用文字按钮，没有引入新图标依赖或字符图标。

## 操作状态

- 保存时使用 revision 前置条件，冲突保留窗口内草稿并显式提供重新载入。
- 生成前保存修改。生成期间禁用文稿输入，状态轮询不会覆盖未保存文字。
- 生成成功依赖本次 job 成功状态；失败保留上次成片但不会显示成本次成功。
- 本次成功后刷新视频 URL 并请求本机打开成片。载入页面不会自动播放声音。
- 导入整篇文稿会替换当前可编辑稿件，并先保存未保存的修改，再由后端备份。

语法检查、接口实际运行与 Edge / 原生窗口截图验收分别记录。静态文件完成不代表视觉或完整流程已经验收。
